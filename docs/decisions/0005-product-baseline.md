# 决策 0005：用户端跨平台栈、双轨计量、ZPay 支付与容量基线

- **状态**：已采纳并落地

## 背景

在完成视觉原型与数据库选型后，需要正式锁定用户端跨平台实现路径、主服务与题库的计量收费模型、在线收款供应商、退款边界以及目标服务器资源预算。

## 决策

1. **三端技术栈分工**：用户客户端统一使用同一套 **Flutter** 工程构建 Web、Android 与 iOS 应用，最大化复用状态管理与界面组件；管理员控制台保持独立的 **React + TypeScript** Web 应用。
2. **双轨独立用量计费**：
   - 主服务按**首次经平台独立查询确认通过的有效任务点数量**计费；排队、执行观察、预完成任务点、普通无编号资料及失败重试均不计费，同一稳定任务点至多结算一次；
   - 题库服务按模型调用消耗的 token 独立计费，不混入主服务单价隐藏收费。
3. **身份映射与资金规则**：一个学习通不可变外部主体对应唯一内部用户与钱包；在线充值供应商确定为 **ZPay（`https://zpayz.cn`）**；正常充值到账余额原则上不开放自助提现退回，未消费预占自动释放，重复付款或异常扣费通过后台人工对账与双类退款（服务退回钱包 / 渠道原路退款）独立处理。
4. **分发与主机容量目标**：移动安装包采用自有 HTTPS 下载站托管（iOS 原生分发须满足 Apple 合规签名与地区资质，默认优先使用 Flutter Web）；单机基准面向约 **2 vCPU / 4 GiB RAM / 30 GiB 磁盘** 设计分层 TTL 清理与异机加密备份。
