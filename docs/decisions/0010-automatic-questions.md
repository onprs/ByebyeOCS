# 决策 0010：全自动章节测验

状态：用户已确认。安排启用题库策略后全自动作答与最终提交，不要求人工确认；本决定覆盖此前的固定人工确认交互。

## 产品行为

用户在安排中选择已发布模型及 `cache_first` 或 `always_llm`。每次保存形成不可变版本。后台按照该版本依次取题、查询答案、映射平台选项或填空、最终提交，并独立读取平台结果。界面不提供逐题确认、最终提交审批或额外手动提交按钮。

单独题库查询保留查询、展示结果与报告错误缓存。管理员手动发起付费模型测试属于维护操作，继续明确该测试会产生用量；它不参与普通自动作答流程。

普通章节测验支持单选、多选、判断、填空和简答。未知题型、无法可信解析的字体/内容、无法唯一映射的答案停止本次执行并说明原因。模型答案不代表正确率保证，也不代表平台已确认完成。

## 执行与恢复

生产路径使用原生 HTTP，沿用平台会话、受限来源、TLS、限速和全局/账号并发。取题和提交位于同一任务租约下，模型调用与最终提交前重新核对暂停、闭户、账号状态和 fencing。

最终提交前重新读取当前表单、题目、选项、图片内容与作答机会；指纹不一致时停止。填写使用确定性映射，保留平台选项原始值和填空顺序，不使用随机答案或模糊匹配。一次提交调用最多发起一次最终 POST。

查询使用任务、冻结安排版本、试卷和题目的稳定幂等键。恢复取得同一查询及原有计费事实，不能因重启重复模型调用或扣费。后台与手动查询共享题库并发名额，等待名额期间可被取消，取得名额后重新核对租约。

`learning_work_runs` 保存运行状态、查询引用和答案摘要，不保存原题、原始图片、答案或平台会话。最终提交前持久化 `submitting`；明确接收后记录 `submitted`。响应丢失或结果不明保留 `submission_unknown` 并只读取平台结果；达到核验上限后记录异常，避免重复最终提交。

平台确认与有效任务点计量保持独立。题库 token 按实际调用事实结算；用量不完整时保留结果并停止自动扣费，可用答案仍可继续自动填写。验证码、身份失效、权限异常与平台限流按实际分类停止或有界退避。

## 兼容

旧 `require_manual_confirmation` 字段仅用于解析旧客户端，请求值忽略，当前视图恒为 `false`。历史安排快照保留原值，新安排保存 `false`。移除旧的 `/api/v1/question-submissions` 人工提交入口，最终平台提交统一由任务编排负责。

缓存行为遵循决策 0006：`always_llm` 跳过精确缓存读取，成功结果允许写入，后续 `cache_first` 可以命中；命中 token 为零。主设计文档与该规则同步。

## 验收范围

本地验证覆盖受控 HTTP 协议、隔离 PostgreSQL、真实题库业务及账本接线、无确认自动运行、提交响应丢失后核验、无效答案停止、用量缺失不扣费和租约/恢复边界。实际学校课程、平台身份、真实付费模型及生产执行仍按对应配置和目标验证，不能由夹具结果替代。
