# 决策 0010：章节测验全自动取题、作答、防重放提交与独立复核

- **状态**：已采纳并落地

## 背景

用户在多课程学习安排中启用测验任务后，期望后台在无人值守情况下自动完成试卷读取、题库查题、填写提交与平台复核闭环；同时必须防止因网络超时或进程重启对同一张试卷发起重复最终提交，或把无法映射的残缺答案强行交卷。

## 决策

1. **全自动无审批闭环**：安排启用题库策略后，系统自动完成测验读取、动态字形几何还原、题库查询、选项与填空确定性映射、最终提交及独立平台只读复核，移除逐题人工确认与手动审批提交环节（历史请求中的 `require_manual_confirmation` 仅作兼容解析忽略，视图恒为 `false`）。
2. **提交前二次核对与防重放持久化**：
   - 发起最终交卷 POST 前，重新拉取当前工作页核对题目、选项序列、图片摘要与剩余作答机会；不一致或存在无法唯一映射的答案、未支持题型、字形歧义时立即中止提交并转入 `needs_attention`。
   - 确认可提交后，**先在数据库 `learning_work_runs` 持久化 `submitting` 意图**再发出网络请求；若交卷响应丢失（`submission_unknown`）或后续崩溃恢复/手动重新调度，系统仅执行独立只读平台复核，严禁二次发送最终交卷请求。
3. **独立查询与面板测试边界**：用户设置中的独立题库查询页仅负责单题查询、结果展示与提交问题报告；题库面板的功能测试明确提示会产生模型 token 消耗且不介入普通课程任务。

## 当前落点与影响

- 支持单选、多选、判断、填空、简答五类题型及三级关卷识别（含保留残留表单的已截止试卷），详见 [外部集成架构](../architecture/integrations.md) 与 [异常恢复机制](../development/runtime-gaps.md)。
