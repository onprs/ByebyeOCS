# 决策 0009：正式学习任务统一采用原生 HTTP 直接执行

- **状态**：已采纳并落地

## 背景

若在生产服务端运行无头浏览器（Headless Chrome）或本地播放器执行视频、文档与测验任务，单并发实例就会消耗数百兆内存与大量 CPU，无法在 1 GiB–4 GiB 的轻量级 Linux 主机上稳定运行多用户并发，且增加容器/图形库攻击面。

## 决策

1. 正式生产任务统一使用纯 Go 实现的 **`chaoxing.HTTPExecutor` 原生 HTTP 协议执行器**，直接读取新鲜章节卡片上下文、按真实经过时间与平台签名规则上报音视频/文档进度并执行章节测验。
2. 从生产配置与部署运行依赖中彻底移除浏览器可执行文件、媒体播放器与音视频解码器；Chrome/Playwright 仅保留在开发维护环境用于前端界面自动化测试。
3. 解除早期为迁就浏览器内存而强加的单并发限制，开放可配置的全局与单账号并发池（上限 `1–256`）及低内存（`2C1G` 起步）systemd 资源配置。
4. 严格维持**执行观察进度、独立平台核验、真实媒体播放证据**三者分离：原生 HTTP 执行记录一律如实标记无真实播放证据（`media_evidence.available = false`）；遇到验证码、真实本人核验、`403/429` 或权限拒绝时立即停止对应任务或按有界冷却退避。

## 当前落点与影响

- 实现位于 `server/internal/adapters/chaoxing/`，覆盖视频、音频、文档与五类题型测验，详见 [任务覆盖范围与完成判定规范](../development/task-coverage.md)。
