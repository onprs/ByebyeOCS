# 决策 0011：由独立题库维护面板统一拥有上游模型与公开目录

- **状态**：已采纳并落地

## 背景

在早期过渡设计中，上游大模型写在题库静态 JSON 文件里，而公开模型条目与微元价格版本又在主平台管理端维护，导致维护员需要在两套系统来回手工对齐 `provider_ref` 编号，极易出现引用失配或职责交叉。

## 决策

1. **单一维护入口（`/panel/`）**：将提供商配置、上游模型增删改与密钥保存、模型连通性/功能测试、公开模型条目发布、只追加微元价格版本及默认缓存策略统一收归独立题库维护面板（`/panel/`）所有。
2. **配置热加载与一对一绑定**：面板修改提供商或上游模型后，原子写回题库配置文件与 `0600` 私密密钥文件并即时热加载至内存模型注册表；数据库通过部分唯一索引约束每个活跃上游模型最多关联一个当前公开条目（支持软删除公开条目释放绑定，完整保留历史价格版本与旧查询引用）。
3. **主平台只读镜像与快照冻结**：
   - 主平台移除模型增删改与题库全局改价写接口，仅通过服务令牌读取 `GET /internal/v1/offerings` 同步 `question_offerings` 只读目录镜像；主管理端侧栏与系统设置仅保留跳转 `/panel/` 的入口（任务监控底部保留用户答案问题报告复核区）。
   - 主平台发起每次查询时将当时的公开条目、微元价格版本、有效输出预算与缓存策略冻结写入 `question_queries`，由主平台钱包与复式账本独立完成预占与结算。

## 当前落点与影响

- 题库数据库第 4–8 号迁移与主数据库第 23–24 号迁移已完成此收敛，实施与联调细节见 [独立题库适配](../development/tiku-adaptation-audit.md) 与 [题库面板治理](../development/tiku-performance-panel-audit.md)。
