# 决策 0006：fork 题库、模型目录与 token 用量

状态：用户已提出需求，采用 fork 与二次开发。公开模型清单和 token 单价由管理员面板配置，初始值待录入；本轮不修改 OCS-Tiku 源码，也不创建新仓库。

## 背景

现有 OCS-Tiku（本地与远程 HEAD `aedb64c55952f7914e4c46d59c732018605a9921`）已经具备：

- 管理员配置上游服务、回答模型和图片转述模型。
- 每次模型调用记录 prompt/completion/total tokens、模型、协议、耗时和状态。
- 题目历史的倒排索引与模糊检索，供 agent 工具使用。

但它不能满足本平台的三项产品要求：

1. 用户不能在请求中选择管理员暴露的模型；当前 `/api/search` 固定使用全局配置。
2. 用户不能在“每次调用模型”和“有缓存时使用已有答案”之间选择；当前搜索流程总是调用模型，历史检索只是模糊候选，不能作为精确缓存。
3. `/api/search` 不返回 token 用量、模型、缓存命中和调用分解，主平台无法据此做可信的按量计费。

## 决策

### 1. 采用独立 fork

fork 一个由项目所有者维护的 OCS-Tiku 版本，作为独立题库服务部署，不复制进 Go 主后端。保留 upstream remote，新增能力以独立模块和 v2 API 为主，尽量不重写上游核心。

生产题库服务只通过私有网络/受保护的服务间认证供主平台调用；不把题库管理页、上游密钥或内部模型配置暴露给普通用户。主平台不直接查询题库数据库。

### 2. 题库也使用 PostgreSQL

主平台与 fork 题库都使用 PostgreSQL。fork 使用独立数据库和角色（例如 `ocs_tiku`），不复用主平台 schema，不做跨数据库 join。两者可位于同一 PostgreSQL 集群或不同主机；以用户部署环境为准。

上游 OCS-Tiku 现有 SQLite 存储不是正式数据源；fork 的模型目录、请求幂等、精确缓存、模型调用和用量记录迁移到 PostgreSQL。当前没有生产题库数据需要迁移。

### 3. 管理员维护模型目录，用户选择公开条目

- 上游服务密钥、真实上游模型标识、温度、提示词等保存在 fork 的管理配置中，不进入用户 API。
- 主平台管理员创建“公开模型条目”（offering）：公开名称、说明、能力、默认/可见状态、单价版本，并引用 fork 中的上游模型。
- 用户只能从管理员已发布且健康的条目中选择；不能提交任意上游模型名、URL 或密钥。
- 用户按安排选择模型；已开始的查询绑定当时的模型版本和价格快照。模型下架不会静默切换，后续任务暂停并提示重新选择。
- 图片题需要视觉能力；由支持视觉的模型直接作答，或由管理员配置的图片转述模型补充，额外 token 明确计入用量。

### 4. 两种作答方式

| 值 | 用户文案 | 行为 |
| --- | --- | --- |
| `cache_first` | 优先使用已有答案 | 先查精确缓存；命中则返回缓存并记录 0 模型 token；未命中再调用模型 |
| `always_llm` | 每次都使用模型作答 | 忽略读取缓存，始终调用模型；成功结果仍可写入缓存供以后使用 |

默认建议为 `cache_first`，用户可逐安排修改。这里的“缓存”只指**精确规范化匹配**，不是现有模糊历史检索。模糊候选不得自动当作缓存答案，也不得自动提交。

### 5. token 用量回传与计费边界

- fork 返回每次查询的模型调用明细：输入、输出、总 token，缓存命中、模型、提示词版本、延迟、完成状态。
- 主平台拥有价格、钱包、预占、结算和账本；fork 只返回 token 事实，不直接修改余额。
- 同一 `request_id` 重试返回同一结果和用量；自动重试不产生第二次模型调用或第二笔费用。
- 用量不完整、超时、模型失败或结果不明时，不自动扣费，进入待核对。
- 缓存命中 token 为 0。是否收取独立的缓存检索费、缓存是否跨用户共享、单价和结算批次仍未确定；未公布前不产生真实扣费。

### 6. 兼容与维护

- 保留 v1 `/api/search` 兼容旧 OCS 客户端；新增 v2 查询接口和内部管理 API。
- 新增模块尽量独立：模型目录、精确缓存、用量回传、幂等、PostgreSQL 存储；不把实验开关或上游密钥暴露到主平台。
- 定期 rebase/merge upstream；每次同步运行 fork 的契约和回归测试。若上游改变核心求解流程，优先适配层，不直接覆盖冲突代码。

## 当前未定

初始模型条目、上游供应商/模型、token 单价与计价精度、缓存检索费、共享缓存开关、缓存 TTL、结算批次与最小记账、是否允许跨学校/跨用户缓存、题目数据的境外处理与保留期限。模型清单与单价在管理员面板维护，不写死在代码中。

这些未定项不阻止设计 API、数据库、管理员模型页和用户选择交互；真实扣费保持关闭。

## 依据与风险

- 现有 OCS-Tiku 没有 LICENSE 文件；这是所有者自己的项目，内部 fork 可用，但公开分发前需补充许可证并核对依赖许可。
- token 数字来自上游模型响应，不是密码学证明；需要周期性账单核对和异常处理。
- 缓存能节省 token，但错误缓存会放大错误答案；必须支持失效、用户报告和人工复核。
- 用户选择模型后，平台仍需对答案质量、平台提交和计费结果分别展示，不能把模型输出的答案当作平台已确认。
