# 决策 0008：全栈正式业务实现范围与受控验证边界

- **状态**：已采纳并落地

## 背景

在基础底座就绪后，项目需要一次性在仓库内完成认证、课程同步、任务调度、复式账本、ZPay 支付、题库编排、SSE 实时流、隐私导出闭户、React 管理端、Flutter 三端客户端及 Linux 部署备份工具链的完整业务闭环，同时严守“不用模拟成功冒充外部真实能力”的红线。

## 决策

1. 在仓库内交付完整可编译、可迁移、可测试的生产级代码（`server/`、`services/tiku/`、`apps/admin/`、`apps/client_flutter/`、`deploy/`），全面对接 `api/openapi.yaml` 真实契约，移除任何前端演示数据层。
2. 本地开发与 CI 验证使用隔离 PostgreSQL 临时库及受控 TLS 协议夹具（`devfixture` 合成登录仅在显式开发编译标签与回环环境下提供，绝不进入默认构建或发布包）。
3. 任何未完成外部授权或现场联调的能力（真实学校课程兼容、ZPay 商户收款、上游付费模型、异机备份目标、移动应用正式签名）保持配置级安全关闭，严禁在生产代码中内置假成功分支。

## 当前落点与影响

- 全套业务模块、跨平台开发脚本与自动化测试矩阵均已落地，验证覆盖面与待现场验收项汇总于 [功能实现全景与验证矩阵](../development/local-implementation.md)。
