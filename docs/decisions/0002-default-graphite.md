# 决策 0002：默认石墨，三种外观保留可选

状态：用户已确认，已在交互原型实施。

## 依据

用户明确反馈：“我已确认此设计大体合适，至于三套配色方案我认为可以保留给用户选择切换，但默认石墨。”

## 决策

- 保留现有管理端与用户端的整体信息结构与核心交互。
- 首次访问、未选择外观或配置值无效时，使用 `graphite` 石墨。
- `grove` 青禾与 `indigo` 靛蓝作为可选外观，不再要求用户只选择其中一套作为唯一产品方案。
- 配色与浅深模式独立；切换不修改业务数据、权限和执行状态。
- 普通用户从个人设置进入，管理员从基础设置进入；两类偏好隔离。

## 原型行为

`AppearanceSettings.tsx` 提供可操作的三色选择与浅深模式。`App.tsx` 统一解析偏好、URL 展示覆盖和导航参数。

本机分别使用 `byebyeocs-appearance-v1:client`、`byebyeocs-appearance-v1:admin` 保存外观。用户 Web 与手机视觉原型共享 client 偏好；切到另一个产品端不会继承对方配色。

URL 有效的 `design/theme` 显式值用于预览覆盖。只有点击选择才保存，三个评审 iframe 不在加载时写偏好，避免互相覆盖。不可用或损坏的存储回落到石墨/浅色，当前页面选择仍可继续。

## 正式实现

普通用户和管理员分别有偏好实体和 API。未登录可使用设备偏好，登录后按内部主体同步；使用版本条件更新，不直接覆盖其他设备的最新选择。正式主题支持 system/light/dark，当前原型为 light/dark。

浏览器检查覆盖首次默认、三色切换、刷新/导航保存、手机继承、双端隔离以及打开评审入口不覆盖用户选择。

## 不包含的决定

本次 UI 确认之后，数据库由 [决策 0004](0004-postgresql.md) 确认为 PostgreSQL；Flutter 全用户端、用量计费、题库独立收费、ZPay 和发布/资源基线由 [决策 0005](0005-product-baseline.md) 确认。外部平台授权和未定价格/配置仍按实际门槛处理。
