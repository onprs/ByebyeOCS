# 用户 Web 与手机设计

用户只需要理解课程、安排、进度与余额，不需要理解 Worker、HTTP 和锁。运营细节仅出现在管理端。

## 登录与首次使用

不提供平台注册入口。学习通身份验证后自动关联内部用户并同步课程。

原型可操作密码、候选扫码、授权勾选、二维码过期和验证码流程。使用“填入演示身份”进入；不发送网络登录请求或保存输入凭据。扫码的真实授权路径尚未核实，因此清楚标注候选和不可扫描。

## 首页

优先展示当前身份、正在发生的学习安排、课程和待确认数量、余额与重要提醒。首页提供有限的课程预览与最近进展，不成为完整课程表或日志页。

桌面主视觉与钱包并列；手机主视觉独立，钱包收为一行余额入口，摘要压缩为三项。手机以更少的首屏信息保持方向清楚。

## 课程与详情

课程卡展示名称、教师、章节、平台确认数量与待完成数量。课程列表可搜索、筛选和同步。

桌面详情采用章节树与进度侧栏；手机将进度变成简短摘要置于章节前。普通附件明确标注“学习资料，不计入任务点”。课程页的安排按钮跳转到统一安排页，并预选当前课程。

原型的章节内容由合成数据生成；平台确认演示会同步更新课程统计。

## 任务安排

桌面：安排列表与工作区并列。工作区由安排内容、优先级与启停、实时状态和历史构成。任务类型和优先级可直接操作；完整范围编辑一次完成。

手机：选择器切换安排，配置默认收为摘要，可展开；新建和编辑使用底部面板。这样能更早看到实时任务，同时保持编辑在同一页面。

### 测验模型与作答方式

启用“测验”后，安排编辑器显示管理员已发布的模型条目和两种作答方式。模型条目展示公开名称、简短说明、文本/图片能力和价格状态；不显示上游模型名或密钥。

- “优先使用已有答案”和“每次都使用模型作答”使用分段选择或可点卡片，说明精确缓存与 token 0 的区别。
- 默认跟随平台默认模型；用户可以显式选择条目。模型下架后显示“需要重新选择”，不静默切换。
- 保存后摘要行显示“标准模型 · 缓存优先”，手机端配置折叠时也保留这一行。
- 任务详情展示模型、模式、缓存命中与来源时间、输入/输出/总 token。缓存命中不显示成“模型已作答”。

当前任务按执行中、等待平台、接下来和已暂停分组。需要人工处理与历史独立标签。预计剩余时间标为估算；详情显示真实媒体无记录的情况，不把模拟执行说成真实观看。

用户修改后保留进行中任务的设置；版本冲突在编辑面板中显式提示，避免覆盖别处的更新。

## 钱包

桌面将余额与说明放左侧，充值选项放右侧；手机按余额、充值、历史顺序展示。

支付面板依次展示待支付、支付成功但待入账、已到账。演示控制单独标明，不向真实平台请求付款。到账更新余额和单条流水，可在订单列表继续查看。

原型充值金额是展示选项。主服务已确定按用量，计量单位为平台已确认的有效任务点；题库按 token 单独收费。具体单价未配置，流水与预占释放仍为示意。正常到账余额原则上不退回，异常资金和未消费预占独立处理。

钱包新增“题库用量”视图：每次查询的模型、作答方式、缓存命中、输入/输出/总 token 和价格状态。缓存命中显示 0 model token；单价未公布时显示“用量已记录 · 单价待公布”，不显示虚假金额。

## 个人设置

保留当前身份和会话、通知、外观、钱包、数据导出、删除申请与退出。外观默认石墨，用户可选择青禾、靛蓝并独立设置浅深模式；本机选择在刷新和跳转后保留，管理员偏好独立。正式跨设备同步、跟随系统模式、后台生命周期和推送按多端架构实现。

## 实现边界

手机界面是 React 容器响应式视觉原型。它验证页面层级、触控布局、底部导航与底部编辑，不证明 Flutter 的 Web 首屏、原生性能、系统推送、支付回跳或商店准入。

正式用户端已确定 Flutter Web + Flutter App，管理员保持 React；首版 Web 先行，App 自有下载站地址暂缓。实现与分发边界见 [Flutter 架构](../architecture/frontend.md) 和 [分发设计](../architecture/distribution.md)。
