# 正式界面设计系统

本文件面向开发维护，约束 Flutter 用户端、React 管理员端和独立题库维护面板。产品与视觉调整依据 [线上 UI 评审](ui-review-online.md)。`prototypes/` 保留已确认的第一轮视觉原型；正式界面以本文件和 `design/tokens.json` 为准。

## 卡片与页脚

- 正式用户端各主页面统一使用页脚滚动布局：短内容贴齐可视区域底部，长内容在正文末尾随页面滚动；页脚后不额外留白，也不悬浮覆盖正文。横向使用统一内容宽度及边距。页脚仅显示“© {年份} ByebyeOCS · 版权所有”与“Created by onprs”，窄屏居中且随系统字号自然换行。

## 视觉与布局

使用中性背景、白色或深色内容面、细分隔线和少量强调色。石墨为默认配色，青禾与靛蓝保留。三种配色使用相同的字体、圆角、间距和组件结构；配色切换不改变页面密度。浅深模式覆盖背景、输入、表格、状态和弹层。

| 项目 | 正式规范 |
| --- | --- |
| 基础间距 | 8px，必要的内部间距可使用 4px |
| 组件圆角 | 内容区 10px，控件及状态标签 6px，对话框 14px |
| 正文字级 | 14px，次要说明 13px，辅助索引最低 12px |
| 标题字级 | 桌面页标题 26px，区域标题 16px，数据展示 34px |
| 控件高度 | 桌面主要按钮 36px；手机主要按钮和触控入口 44px |
| 普通内容区 | 最大 1,280px，桌面左右内边距 32px，手机 16px |
| 宽表工作区 | 最大 1,440px；主管理端用于任务、财务页，题库用于记录表格 |
| 桌面导航 | 管理端侧栏 224px，顶栏 64px；用户端顶栏与内容区对齐 |
| 详情与编辑 | 桌面右侧栏 600px；手机底部弹层；简短确认仍使用对话框 |

宽表在自己的容器内横向滚动，溢出时在边缘显示阴影。任务与账号列表在手机上改为带字段名的堆叠行，不再横向滚动。侧栏、标题、表单和普通内容不能依靠放大整页宽度容纳表格。手机主导航保留触控面积和安全区。

数字启用等宽数字特性。正式界面使用无衬线字体及系统中文回退；Flutter 保留项目已有的本地字体资源。界面不依赖外部字体服务。

## 共享变量

唯一编辑入口为根目录 `design/tokens.json`，包含三种配色的浅深颜色、尺寸与字级。`scripts/generate-design-tokens.py` 生成：

- `apps/admin/src/styles/tokens.css`。
- `services/tiku/internal/platform/panel/assets/tokens.css`。
- `apps/client_flutter/lib/design/palette_data.dart`。

在仓库根目录使用 Python 3.10 或更高版本执行以下开发维护命令：

```sh
python3 scripts/generate-design-tokens.py
python3 scripts/generate-design-tokens.py --check
```

Windows 可使用同版本的 `python` 或 `py -3`。生成脚本通过自身位置定位仓库，不依赖维护者的绝对目录。题库是独立 Git 子模块，其生成产物也需要随题库变更保存。独立构建题库时直接使用已经生成的 CSS。

生成过程校验常用正文、辅助文字、选中态和状态标签的前景/背景组合，要求对比度至少 4.5:1。调整颜色时同时检查浅深模式。状态还应包含中文文字或图标，不能只通过颜色区分。

## 组件与交互

Flutter 共享组件位于 `apps/client_flutter/lib/design/`，管理员端位于 `apps/admin/src/components/ui.tsx`。题库维护面板使用原生 HTML 与 JavaScript，复用共享 CSS 变量和相同布局约束。

- 按钮分为主要、次要、文本与危险操作。一个区域只突出当前主要操作；低频操作可以收入“更多操作”。
- 状态使用小圆角标签。绿色表示平台确认、可用或成功；琥珀表示待核验、提醒或待处理；红色表示失败或限制。
- 普通页面按“标题与操作、筛选、摘要、主要内容”排列。辅助编号与次要说明不应超过业务内容的层级。
- 详情与表单使用固定标题区、可滚动正文和操作区。关闭按钮、Esc、焦点恢复与键盘操作属于验收范围。
- Flutter 的 `showAdaptivePanel` 为安排编辑与任务详情选择桌面侧栏或手机底部弹层。手机输入键盘出现后保留保存入口。
- 题库模型列表显示名称、状态、能力、价格与缓存摘要；详细编号、价格版本与测试记录进入详情侧栏。模型编辑、公开价格编辑分别分组，标题与操作栏固定。
- 页签、侧栏导航与设置分组共用滑动选中指示器。首次绘制直接落位，不执行入场滑动。返回页面时恢复离开前的滚动位置。
- 题库表单的操作按钮通过明确的表单编号关联原生表单；不能通过可能被同名输入框遮蔽的 DOM 属性获取编号。
- 说明优先放在相关字段、异常、空状态或确认操作处。页面标题不重复展示上级小标题，首页不使用宣传式大卡片。
- 课程同步在首次进入首页时自动开始或接续运行中的任务，显示实时课程数量；不提供手动同步入口，仅在失败时提供重试。
- 标签页使用 `StatefulShellRoute` 保持各分支页面与滚动位置；切换时内容先淡出到页面背景，再淡入新分支，顶部与底部导航保持可见。详情页使用 220ms 滑入。
- 首页由问候、学习概览、钱包、带图标的统计、课程封面卡片、学习安排与最近确认组成；课程封面由主题色几何图形生成。
- 登录页左侧为品牌区：大标题、事实性说明与课程同步/任务安排/平台确认三项能力标识，配低对比几何背景；右侧表单在可用高度内垂直居中，内容超出视口时整页滚动。手机端只保留紧凑品牌标题。登录表单只要求学习通账号与密码，学校信息取平台返回值，不提供验证码假设输入。
- 卡片本身使用边框分隔；阴影保留给菜单和弹层。减少动态效果的系统偏好应生效。

## 页面事实

任务界面分别展示平台确认、执行观察和媒体记录；没有真实播放证据时显示“无播放记录”。钱包以服务端状态为准，未定价、未收费、付款状态与到账状态按事实展示。独立题库查询页仅查询、展示与报告问题；安排中的自动答题流程沿用既定业务权限。

管理端不再提供题库查询页；模型、价格、查询记录与缓存统一在独立题库维护面板查看和维护。答案报告由主服务保存，复核入口位于任务监控。正式面板是 `services/tiku/internal/platform/panel/assets/`，随 `cmd/ocs-tiku-fork` 内嵌发布。

`services/tiku/frontend/` 仍被根级上游兼容服务和其单文件发布脚本使用，保留为独立兼容前端。本轮未删除其代码，也不将它作为正式 `/panel/` 的构建来源。

## 验证入口

- 管理员端：`npm --prefix apps/admin run check`、`build` 与 `test:e2e`。布局回归覆盖 1,920、1,440、1,280、1,024、768 和 390px，以及三种配色的浅深模式；验证详情关闭后恢复焦点。
- Flutter：在 `apps/client_flutter` 下运行 `flutter analyze`、`flutter test` 与 `flutter build web --release`。安排编辑测试覆盖桌面、手机和键盘遮挡。
- 题库：`go -C services/tiku vet ./...`、`go -C services/tiku test -race ./...`；浏览器流程由隔离 PostgreSQL 与受控上游夹具运行，覆盖模型维护、公开价格、测试确认、缓存失效和只读权限。
- 需要截图时，管理员布局回归可通过 `BYEBYEOCS_UI_SCREENSHOTS=1` 输出到被忽略的 `.local/screenshots/ui-review/admin/`。现场证据和维护环境数据不作为公开用户的前提。
