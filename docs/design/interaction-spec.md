# 交互状态规范与原型对照

> **适用范围**：开发维护环境。本文第一部分规定正式三端（Flutter 用户端、React 管理端、独立题库面板）的通用交互状态准则；第二部分说明 `prototypes/` 历史视觉原型的边界与回归检查方法。

## 1. 正式三端通用交互准则

### 1.1 加载、空态与异步反馈

- **首屏与局部加载**：首屏数据未就绪时使用与真实内容等高同构的骨架屏或顶部细进度条，杜绝加载完成后的版面剧烈跳动；后台 SSE 触发的静默刷新保留当前列表与滚动位置，不闪回全屏空白骨架。
- **按钮提交保护**：所有触发网络请求的按钮在等待响应期间保持原有宽度并切换内联加载指示器，同时禁用重复点击；涉及资金、创建订单、调账、退款与发布配置的请求自动附带 `Idempotency-Key`。
- **缺失值与空状态**：表格或详情中缺失的单一字段统一显示全角破折号 `—`；列表为空时使用克制的标题加一句操作引导（必要时附单个主动作按钮），不堆砌插画或开发者提示语。

### 1.2 错误呈现与乐观锁冲突

- **就地错误提示**：表单校验失败紧贴对应输入项下方提示；后台刷新失败在页面顶部展示非阻塞 `RefreshError` 条并保留已有旧数据可读；仅当初始加载完全失败且无本地快照时展示带“重试”按钮的 `ErrorState`。
- **并发编辑版本保护**：学习安排、计费配置与用户偏好更新均携带资源 `version`。当多标签页或多管理员并发修改引发 `409 Conflict` 时，界面明确保留用户当前输入草稿并提示远端版本已更新，引导刷新核对后再提交，禁止静默覆盖他人更改。
- **分层弹层规则**：常规新建与复杂编辑在桌面端统一使用右侧抽屉（`600px`），在移动端使用底部弹层（Bottom Sheet）；模态居中对话框（Modal Dialog）仅限用于账号删除确认、权限/资金步进验证（`StepUpDialog`）等短小高危阻断确认。

## 2. `prototypes/` 历史视觉原型对照与检查

仓库根目录下的 `prototypes/` 保存了项目第一阶段用于评审三套外观与核心交互流的 React 原型工程。该工程与正式生产代码完全解耦：

| 维度 | `prototypes/` 视觉原型 | 正式生产三端（`apps/*`、`services/tiku`） |
| --- | --- | --- |
| 数据与状态 | 浏览器内存与 `localStorage` 合成数据，含顶部“演示场景”控制条 | PostgreSQL 持久化存储、REST + SSE 实时同步，无任何演示控制条 |
| 认证与权限 | 前端模拟角色切换，无密码校验与服务端拦截 | 学习通探针绑定、Web Cookie/CSRF、原生双令牌、管理员 Argon2id + TOTP + RBAC |
| 题库与计费 | 本地静态模型数组与模拟两阶段点击入账 | 独立 `ocs-tiku-fork` 服务、`/panel/` 面板目录同步、整数分复式账本与 ZPay 验签 |
| 移动端实现 | React 窄屏容器模拟 | 真实 Flutter 跨平台工程（Web / Android / iOS） |

### 原型回归检查命令

维护者在修改 `prototypes/` 对照代码时，可在仓库根目录执行构建与浏览器自动化检查（需本机安装 Node.js 22+ 与 Chrome/Chromium）：

```bash
# 1. 构建原型工程
npm --prefix prototypes run build

# 2. 在终端一启动回环预览服务（默认 127.0.0.1:5186）
npm --prefix prototypes run dev

# 3. 在终端二运行 UI 交互与 120 个视图变体检查
npm --prefix prototypes run test:ui
```

脚本 `prototypes/scripts/verify-ui.mjs` 会校验默认石墨加载、三套配色与浅深主题切换隔离、模拟状态流转及桌面/窄屏（`390×844`）无横向溢出，并将结果输出至未纳入版本追踪的 `prototypes/artifacts/` 与 `prototypes/screenshots/`。
