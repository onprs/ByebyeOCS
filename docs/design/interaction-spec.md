# 交互说明与原型验收

## 本地预览（开发维护环境）

起点为已有源码的项目根目录，要求 Node.js 22.12 或以上及 npm。无需 Go、Flutter、Docker 或真实账号。

```bash
npm --prefix prototypes ci
npm --prefix prototypes run dev
```

默认地址：<http://127.0.0.1:5186/review>。端口被占用时 Vite 明确报错，不擅自接管其他项目的服务；可在命令末尾传入 `-- --port 其他端口`。

开发服务默认仅监听回环。通过其他设备访问时需要明确配置监听地址和开发网络规则，这不属于正式公网部署方案。

## 建议评审顺序

1. 在三方向入口切换管理端、用户端和手机预览，比较整体布局与品牌感。
2. 进入管理端账号页，全选当前页，尝试批量并发配置和暂停任务；查看账号抽屉。
3. 进入任务监控，筛选异常，查看任务的处理记录、平台确认与媒体记录；暂停或继续适用任务。
4. 进入用户课程详情，展开第三章，核对普通附件与任务点的区分。
5. 在任务安排中编辑名称、多课程、类型、章节与优先级；查看不同实时分组与历史。
6. 在同一个安排编辑器选择“测验”，切换公开模型和“缓存优先/每次调用模型”，保存后查看摘要和任务详情中的缓存命中与 token。
7. 从管理端侧栏进入“题库维护面板”；在“模型与价格”发布公开模型、填写能力与输入/输出 token 价格，切换可见性、默认与缓存策略。回到用户安排确认新模型可选及下架提示。再到“系统设置 → 计费策略”填写有效任务点单价和价格版本，确认“启用真实扣费”仍关闭。
8. 创建充值订单，先触发“演示：支付成功”，检查余额不变；再触发“演示：余额到账”，检查余额和明细主动更新；切换“题库用量”查看 token。
9. 在手机窄屏检查底部导航、安排切换、配置展开、模型/作答方式和底部编辑。
10. 进入个人设置的外观区域切换石墨、青禾、靛蓝，再切换浅深主题，检查刷新/跳转保存与管理端独立性。首次默认石墨。

## 可操作与模拟边界

| 类别 | 已有交互 | 边界 |
| --- | --- | --- |
| 导航 | 双端独立导航、全局搜索、带条件定位、手机底栏 | 无真实认证拦截 |
| 账号 | 搜索、筛选、排序、分页、多选、批量配置、限制与解除 | 本地合成身份，无真实平台登录 |
| 任务 | 详情、暂停、继续、取消、重新调度、模拟平台确认 | 不运行学习任务，不自动发送进度 |
| 安排 | 新建、编辑、范围、类型、优先级、启停与版本冲突 | 不产生真实调度队列 |
| 模型与缓存 | 选择公开模型、缓存优先/每次调用、管理员可见性、任务 token 展示 | 不调用真实模型；缓存与 token 为合成数据 |
| 支付 | 合成订单、支付与入账两阶段、单次入账、持久化 | 无真实支付、账本或服务端安全保证 |
| 设置 | 通知、主题、配置保存、模拟连接测试、审计 | 部分安全规则仅表达约束，无正式服务 |
| 题库 | 公开模型目录、缓存策略、token 用量、连接测试交互 | 不调用 OCS-Tiku fork，不查询或提交测验 |
| 数据 | 导出合成数据、记录删除或申诉意向 | 正式工单和法定保留流程待实现 |

状态保存在浏览器 `localStorage`，仅用于演示；不包含输入的登录密码。顶部“演示场景”可以恢复初始合成数据。跨标签页通过本地版本冲突演示协作边界。

## 构建与检查

```bash
npm --prefix prototypes run build
npm --prefix prototypes run test:ui
```

浏览器检查需要本机 Chrome，或通过 `PROTOTYPE_CHROME` 指定 Chromium 可执行文件；该依赖仅用于原型截图和验证，正式 Go 服务无此默认要求。预览地址可用 `PROTOTYPE_URL` 覆盖。

检查脚本位于 `prototypes/scripts/verify-ui.mjs`，覆盖默认石墨、三色切换与偏好持久化/隔离，以及账号操作、任务状态、安排范围、版本冲突、模型选择/缓存模式、token 展示、钱包分阶段入账与幂等、人工调整、课程计数、模拟验证码和手机编辑；另检查三方向、浅深主题、桌面及手机共 120 个页面变体。

本地运行后，检查结果写入 `prototypes/artifacts/ui-verification.json`。这些检查只能证明合成前端交互，不能证明真实学习平台接口、支付安全、权限隔离或 Flutter 可用。

截图在本地生成到 `prototypes/screenshots/`。桌面图为整页，手机图为 390×844 视口。截图与 `artifacts/` 下的验证报告不进入版本管理或正式发布包，可通过上述脚本重新生成。对比拼图用于方便审阅，实际原型仍可交互。

## 当前阶段

用户已确认整体 UI，决定默认石墨并保留三种配色。技术架构和分阶段路线已补充；题库 fork 的模型目录、精确缓存和 token 用量已进入设计与原型，但尚未修改 OCS-Tiku 源码或启用真实计费。不能把原型数据层、角色模拟和付款演示当作正式业务实现部署。
