# 题库查询超时、输出预算与幂等恢复架构

> **适用范围**：开发维护环境，说明主服务（`server/internal/questions`）与独立题库服务（`services/tiku/internal/platform`）在长推理大模型调用下的超时所有权、输出预算冻结、在途回收与未知结果释放机制。

## 1. 调用生命周期归属与超时包络

深度推理模型在返回首字节前可能耗时数十秒至数分钟。若主服务因本地 HTTP 等待超时直接断开连接并将查询标为“结果未知（`needs_review`）”，该幂等键将被永久锁定，导致整张测验无法继续自动作答。为此两服务确立了明确的生命周期归属：

1. **题库服务独占模型调用生命周期**：`ocs-tiku-fork` 收到 `POST /api/v2/answers` 后，在脱离客户端 HTTP 连接取消信号的后台协程中执行上游模型请求与结果持久化。即使主服务等待超时先行断开 HTTP 连接，题库侧的模型调用、token 计量与缓存落库仍完整执行完毕。
2. **统一上游截止时间**：题库 `limits.timeout_seconds` 支持配置最高 `900s`（默认 `90s`），上游模型 HTTP 客户端的首包响应头超时与整体截止时间对齐，避免长思考模型在输出首字节前被提前切断。
3. **主服务等待窗口返回可重试挂起**：主服务 `questions.timeout`（范围 `1s–15m`，内置默认 `330s`，部署安装脚本默认生成 `95s` 以包络题库默认 `90s`）仅控制单次同步等待时长。等待窗口到点而题库尚未返回时，主服务向调用方返回 `HTTP 202`（`code = fork_pending`、`retryable = true`），本地查询保持 `pending` 并保留冻结预占；后续同幂等键重试直接从题库读取已完成结果，全程仅触发一次上游大模型计费调用。

## 2. 输出 Token 预算三级收敛与快照冻结

- **公开条目有效预算计算**：题库面板发布公开条目时输出 `max_output_tokens`，取**面板全局上限（默认 `32768`）、上游模型单模型配置值与模型自身能力上限**三者的有效最小值。
- **新查询预算冻结（迁移 34）**：主服务发起新查询时，读取并冻结当前公开条目的有效输出预算存入 `question_queries`（客户端显式传入更小 `budget.max_output_tokens` 时受该上限约束）；历史已存在的在途查询在恢复重放时严格沿用首次冻结的预算值，保证题库幂等请求指纹前后完全一致。

## 3. 在途查询自动回收与前置失败恢复

### 3.1 后台在途回收器（每 30 秒巡检）

针对超过同步等待窗口后客户端未再主动重试的 `pending` 查询，主服务后台每 `30s` 扫描一次（单批最多原子抢占 `20` 条），调用题库只读内部接口 `GET /internal/v1/requests/{idempotency-key}`（不触发新模型调用）：

- 返回 `completed`：使用主库已冻结的价格快照与题库返回的完整响应走标准完成结算链路；
- 返回 `pending`：题库仍在执行中，顺延下次检查时间；
- 返回 `failed` / `unknown` / `expired` 或记录缺失（`pending_record_missing`）：按实际错误码收敛查询状态或转入待复核。
- 管理端可通过 `GET /admin/api/v1/question-recovery`（及任务监控���题库状态区）观测回收器运行轮次、处理计数与最近错误码。

### 3.2 前置失败白名单恢复与未知结果受控释放

- **前置白名单恢复**：对于明确发生在**发起上游模型调用之前**的错误（如钱包余额不足、公开条目暂时禁用），用户在充值或管理员恢复模型后，允许沿用原查询编号重新发起新代次预占（保留首次冻结的单价与收费判定，绝不复用已关闭的旧 Hold）继续完成查询。
- **`request_unknown` 受控人工释放**：一旦请求已发往上游且因网络故障无法确认是否产生模型计费（如 `request_unknown`、`upstream_timeout`），系统绝不自动重发第二次调用。管理员核实上游账单确认未产生有效调用后，可调用 `POST /admin/api/v1/question-queries/{id}/releases` 填写非空审计原因执行受控释放（已包含 `usage_incomplete` 等实际用量事实的记录严禁释放）——系统释放关联预占，将原幂等键归档重命名为 `<原键>#released-<version>` 留存审计，从而允许后续重试使用干净的原业务键重新作答。
