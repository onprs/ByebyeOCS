# 学习通与独立题库集成架构

> **适用范围**：开发维护环境，说明 `server/internal/adapters/chaoxing` 原生协议适配器及主服务与 `services/tiku` 独立题库之间的跨服务集成契约。

## 1. 学习通原生 HTTP 适配器（`adapters/chaoxing`）

正式适配器从早期协议研究验证中提炼纯 Go 实现（保留研究目录隔离不参与构建），严格围绕**身份探针、目录发现、原生 HTTP 执行、独立平台复核**四项职责运作：

### 1.1 单次操作隔离 Cookie 作用域與安全传输

- 课程同步（从拉取课程列表到并发遍历各门章节）或单次测验执行（从读取工作页、加载字体到提交表单）各自创建按**平台实例与原始会话指纹隔离的内存 Cookie 容器**。
- 操作过程中上游返回的临时会话 Cookie（如路由或防重放短期 Cookie）在当次操作内自然接力，防止目录或工作页返回 `403`；操作结束后临时容器即刻销毁，**不反向覆写数据库中持久加密保存的原始平台会话**。
- 所有出站 HTTP 请求强制校验目标域名白名单、HTTPS 协议（仅把学习通可信自有域的遗留图片 HTTP 链接安全升级为 HTTPS）、DNS 解析非内网回环地址，并通过平台级令牌桶遵守 `RequestInterval` 最小请求间隔。

### 1.2 各任务类型原生协议与完成证据边界

所有任务统一贯穿章节卡片真实页码 `card_index`，杜绝同章节多页卡片错位：

1. **普通视频与明确音频**：读取新鲜卡片与媒体状态接口获取对象 `objectid`、总时长 `duration`、历史保存点、上报间隔及 `enc` 签名材料，按真实流逝时间周期上报播放进度，并在结尾发起独立完成核验。卡片附带的纯前端定时抓拍配置不参与服务端进度验签，故不无故阻断任务；仅当上游响应实际要求验证码或本人身份核验时立即停止该任务并标记 `needs_attention`。
2. **文档与阅读任务**：不因初始卡片缺少完成字段而误阻断；调用 `/ananas/job/document` 接口后，若平台明确返回完成标志（包括“考核点已经完成”等平台确认语义）或紧随的一次幂等只读复查确认通过，即记录平台确认。
3. **章节测验任务**：读取测验工作页 HTML，先判定是否处于未开放或已截止状态（含顶部提示“已截止，不能作答”但页面仍残留表单控件的场景，统一前置判定为 `quiz_closed`）；若存在 `font-cxsecret` 动态混淆样式，使用内置 Source Han Sans 1.000 几何轮廓参考库还原文字；支持**单选、多选、判断、填空、简答**五类题型。测验卡片本身不含可靠完成位，独立复核严格检查工作页中带具体取值的已提交答案或明确批阅得分，单独出现空白“本次成绩”字样绝不误判为已完成。
4. **未支持活动类型（`other`）**：直播、讨论、复杂互动题等未验证类型如实标记为未支持，保留任务点计数而不伪造执行。
5. **真实播放证据分离**：原生 HTTP 请求不启动真实音视频解码渲染，因此所有由 `HTTPExecutor` 执行的任务均如实标记 `media_evidence.available = false`。

## 2. 独立题库（`ByebyeOCS-Tiku`）跨服务契约

主平台通过内网/回环 HTTP 与 Bearer 服务令牌调用独立题库服务，上游模型凭据与计费账本严格解耦（见 [决策 0006](../decisions/0006-tiku-fork-token-billing.md) 与 [决策 0011](../decisions/0011-tiku-panel-catalogue.md)）：

### 2.1 公开模型目录镜像同步

- 题库维护员在 `/panel/` 配置提供商与上游模型后，一对一发布公开条目（含稳定条目 UUID、公开标识 `offering_id`、绑定上游 `provider_ref`、显示名称、视觉支持标志、有效最大输出预算 `max_output_tokens`、微元费率版本及允许的缓存期限）。
- 主平台通过 `GET /internal/v1/offerings` 定期及按需同步公开目录至本地 `question_offerings` 镜像表，校验字段合法性与模型健康状态；用户界面仅展示可见条目名称与图片支持标记。

### 2.2 v2 精确缓存、视觉转述与答案规范

主平台调用 `POST /api/v2/answers` 时携带稳定的 `Idempotency-Key`、公开条目对应的模型引用、缓存作用域（默认 `user` 级 HMAC 隔离键；仅在主平台、题库全局及条目三级开关同时开启时允许 `shared`）与请求级 `cache_policy: {allow, ttl_days}`：

- **严格精确缓存**：缓存键综合规范化后的题型、题干、完整选项序列、图片内容 SHA-256、提示词/规范化版本（含 `/choice-text-v2`）、实际作答与转述模型的端点/密钥摘要及有效输出预算。任何一项不同均视为未命中，严禁用历史模糊相似题充当缓存。
- **完整选项保留与重排映射**：v2 解析器完整保留单选题与判断题 `<answer>` 中的完整选项文本（防止 `HTTP`、`WHO`、`true` 等多字符答案被截断为首字母），主平台拿到答案后结合当前试卷实时选项文本与字母做双向一致性映射，遇到冲突或无法唯一映射时停止提交并支持在用户显式重试时开启最多三代重查。
- **非视觉模型图片题转述**：当题目包含图片而用户所选模型不支持视觉输入时，题库服务可自动调用配置的 `caption_model_id` 先生成客观图面转述，再交由主模型作答；响应中的 `usage.calls` 数组分别列出 `caption` 槽位与 `answer` 槽位的 token 消耗，账目完全透明。
