# 2C4G / 30GB 首期容量基线

用户已给出约 2 vCPU、4 GB 内存、30 GB 磁盘的主机预算。本节是工程预算和保护方案，不是已测容量或保证的真实账号并发数。实际按供应商的 GB/GiB、系统占用、文件系统与 `MemTotal` 校准。

## 1. 部署组成

同机运行一个 Go 主应用、一个 fork 题库 Go 服务、原生 PostgreSQL（同一集群内的独立数据库/角色）、HTTPS 入口及必要监控/备份工具。Flutter Web 和管理端提供预构建静态资源；Android/iOS 产物在构建环境生成并交由独立下载站托管。

题库 fork 是独立进程，不复制进主应用。若题库查询量增长或需要独立发布，可迁到单独主机；迁出时只改私有地址和服务认证，不改主平台业务契约。2C4G 同机部署只适合受控试点，不能据此承诺大规模模型并发。

## 2. 内存预算

| 部分 | 初始预算 | 说明 |
| --- | --- | --- |
| Go 主应用 | 384–640 MiB 常态目标 | 候选 GOMEMLIMIT=512MiB；观察/SSE/上传峰值另测 |
| fork 题库 Go 服务 | 128–256 MiB 常态目标 | 模型调用在外部网络，进程主要处理图片与 JSON；大图上限需限制 |
| PostgreSQL 总体 | 768–1024 MiB 目标 | 同一集群承载主库与 `ocs_tiku` 两个数据库；不分两个 PG 实例 |
| 系统、代理、基本监控 | 512–768 MiB | 随发行版校准 |
| 备份/清理低峰增量 | 128–256 MiB | 限制并发，避免与资源峰值重叠 |
| 未分配余量 | 尽量保留约 1 GiB | 用于页缓存和突发；实际按可用内存调整 |

Go CPU 并行度按 2 核配置。候选 PostgreSQL 起点为 `shared_buffers=256MB`、`work_mem=4MB`、`maintenance_work_mem=64MB`、`max_connections=30`；主应用池最多 8 个连接、fork 最多 4 个、最少 2 个。`work_mem` 可被一个查询中的多个操作和多连接同时使用，不能据此宣称固定总占用。

同一 PG 集群使用独立数据库和角色，避免两个 PostgreSQL 实例重复占用内存。若把 fork 迁到独立主机，其 PG 内存/连接必须重新分配，不沿用同机预算。

这些是实施和压测起点，未修改本机或任何远程服务器的配置。

## 3. 磁盘预算

| 部分 | 预算（GB） |
| --- | ---: |
| 系统与原生依赖 | 6 |
| PostgreSQL 数据与索引（主库 + `ocs_tiku`） | 8 |
| 本机 PostgreSQL WAL 工作空间 | 2 |
| 应用/journald/备份工具日志 | 1 |
| 题库临时图片、导出与备份暂存 | 3 |
| 程序版本与 Web 静态资源 | 2 |
| 安全余量 | 8 |
| 合计 | 30 |

题库原图默认 24 小时、答案缓存 7 天，缓存 TTL 与共享开关直接限制增长；不能把无限历史题目和图片长期堆在 30GB 主机。缓存命中统计和 token 用量按聚合/财务层保留，不复制完整题目。

这是规划分配，不是已建立分区或硬配额。镜像初始占用超过预算、数据索引膨胀或 WAL 积压时应及时调整；不能删除未归档 WAL 或资金数据来保持表面可用。

只保留当前和上一可回滚程序版本。下载站安装包、长期加密备份和归档凭证不堆在应用主机。较大导出改用流式异机输出，不能假定 3GB 暂存能容纳整个数据库。

磁盘 70% 提醒、80% 阻止新执行/题库/充值订单、90% 维护保护，规则见 [数据保留](data-retention.md)。

## 4. 调度和连接起点

- 全局原生执行名额 4；账号默认 1，可经授权验证后提升，代码支持同账号不同任务并发。
- 题库并发 2；图片请求受最大像素/体积、单请求超时和用户配额约束。课表同步、平台核验和支付查单分别有界，支付不排在学习执行后面。
- 同一用户相同题目的并发查询合并等待；不同模型/模式/缓存作用域不合并。缓存未命中才调用模型，缓存命中不占模型并发。
- token 用量只记录数值和必要摘要，不在每 15 秒进度检查点里重复写完整题目或模型输出。
- 状态变化立即持久化；过程观察约 15 秒合并一次，心跳合并更新而非每次追加完整历史。
- SSE 只订阅当前权限范围，连接和缓冲有上限，慢客户端断开后从持久化游标补偿。
- 任务队列存在 PostgreSQL，不为每个排队任务创建 goroutine，不为每个在线客户端创建数据库连接。

上述值是本地资源起点，平台出现身份、权限或 403/429 等异常时仍停止相关操作。不能因为本机资源空闲就持续提高外部平台并发。

## 5. 压测与验收

按以下场景分别测量，不把账号数当唯一自变量：

1. 不同活跃任务、排队任务、SSE 连接和查询量组合。
2. 钱包争用、支付重复通知、到账峰值与学习检查点同时发生。
3. 题库大图、超时、重试、缓存命中/未命中、模型并发和管理员报表；同机与独立部署分别测量。
4. 备份、归档积压、autovacuum、磁盘压力与程序重启。

记录 CPU、RSS、goroutine、FD、连接数、数据库锁/事务延迟、队列年龄、事件补偿延迟、到账时延及异机可恢复点。先使用可控上游模拟器，再对明确授权的真实账号小规模验证。

达到内存/磁盘保护阈值、资金不变量失败或备份目标失效时停止增加负载。没有这些证据前，不承诺 2C4G 能支持某个大规模真实账号数。
