# 数据保留、清理与恢复默认方案

状态：用户授权工程侧决定。本节保留默认保留期及生产恢复目标；当前已实现有界清理、加密逻辑备份和隔离恢复工具，生产持续WAL方案仍按下文单独验收。2C1G低并发起点与2C4G/30GB规划见[容量记录](capacity.md)。

## 1. 分层保留

| 数据 | 默认保留 | 清理与例外 |
| --- | --- | --- |
| 原始学习通密码 | 不持久化 | 一次登录请求内使用，不写日志、审计或备份 |
| 加密平台会话 | 有效授权期间 | 撤销立即停止使用；过期或撤销后 24 小时内清理密文，备份按保留窗口自然淘汰 |
| 登录/验证挑战 | 有效期 10 分钟 | 不含秘密的状态追踪最多 24 小时；挑战不得无限复用 |
| 日常应用/HTTP 日志 | 7 天 | 先脱敏；应用日志和 journald 总预算 1 GB，按时间和大小同时轮转 |
| 任务过程明细、错误摘要 | 30 天 | 观察检查点更新而非每秒追加；未解决故障可最小范围延长并记录原因 |
| 用户可读任务历史摘要 | 180 天 | 当前任务不删除；最小规范任务键、收费去重键及财务关联证据独立保留 |
| 课程历史快照 | 7 天 | 当前课程/章节记录持续更新；过期快照不影响当前课程列表 |
| 共享章节卡片目录 | 30 分钟 | 仅保存课程资源卡片页码；内存最多 4,096 条，持久缓存到期后按每批 500 行清理，不包含个人状态或会话 |
| 题目原图与临时附件 | 24 小时 | 只处理必要图片；超期需重新核对原题，不自动重新付费查询 |
| 原题/答案查询缓存 | 默认 7 天，最长 30 天 | 显式请求策略控制实际有效期，默认用户隔离；查询中和待处理异常按最小必要范围保留，用户可申请删除 |
| fork 维护操作审计 | 180 天 | 登录、模型状态与测试、缓存失效；不保存私密凭据，每批最多500行 |
| 题库 token 调用明细与价格快照 | 明细 30 天，已结算汇总长期 | 结算所需查询 ID、token 汇总、价格版本和账本关联不随普通明细删除；原始题目按 7 天/24 小时层处理 |
| SSE 投递流 | 3 天 | 游标过期重新取快照，不能无限补偿或缓存所有事件 |
| 已投递 Outbox | 7 天 | 未投递事件不能按年龄直接删除 |
| 已解决支付 Inbox 脱敏载荷 | 30 天 | 未解决、争议或对账差异继续保留；支付事实、订单与账本不随载荷一起删除 |
| 普通管理员/安全操作审计 | 180 天 | 资金操作审计进入财务保留层；不含密码/Cookie/密钥 |
| 小时聚合指标 | 30 天 | 无个人身份标签；之后保留日聚合 |
| 日聚合运营指标 | 365 天 | 仅保留必要统计，不保存可还原题目或身份的数据 |
| 账本、充值/消费/退款、可计费用量证据、资金审计 | 不设普通 TTL 自动删除 | 保留最小必要事实，按实际法定期限归档；具体法律期限按经营主体和记录类别核定，不能用运行日志期限覆盖 |

财务长期保留不等于无限保存姓名、Cookie、完整题目和原始 HTTP 响应。原始内容到期后保留脱敏业务编号、金额、价格版本、计量依据摘要与审计关联；依法允许删除或匿名化的个人信息单独处理。

## 2. 用量计费证据

主服务按“平台已确认的有效任务点”计费，需保留平台确认事实和去重键作为用量证据。仅保留本地计时不能证明实际服务用量，更不能证明真实播放。

计费证据与普通进度明细分层：用于结算的规范用量事件、去重标识、单位/精度、价格快照、确认依据和账本引用不可随 30 天过程日志一起删除。用量事件更正通过冲正/补记，不直接覆盖已结算事实。

等待、暂停和自动重试不会单凭时间流逝产生新收费事件；实际计量和失败成本规则未明确前不开启真实扣费。

## 3. 清理策略与磁盘保护

每天低峰按有限批次清理，初始每批最多 500 行或等价资源量；单批事务和作业总时长有上限。索引覆盖过期时间，先保留财务/审计引用，再清理原始内容。不能级联删除充值、journal、幂等或有效任务。

主服务的题库内容清理写入显式过期标记，保留未落定账务及异常查询。正式题库服务不落盘原始题图；精确缓存到期即清除原文，查询答案默认7天，token调用明细30天。已过期的幂等结果清空载荷并保留请求键、摘要及用量汇总，同键不重新调用模型。两服务启动时先进行一次有界维护，此后按各自周期运行，每次最多30秒。

优先更新最新检查点，合并过程观察，不把每次心跳和 UI 刷新写成新行。清理后依靠正常 autovacuum 回收可复用空间；不通过手工删除 PostgreSQL WAL 文件释放磁盘。

默认阈值：磁盘使用达到 70% 提醒并核查增长；80% 暂停新学习执行、题库请求、充值订单及非必要导出；90% 进入维护保护，保留既有订单核验与必要账务处理空间。实际无法持久化通知时返回可重试错误并报警，恢复后主动查单，不能虚假应答成功。

系统不会在空间不足时删除账本或未归档 WAL 来继续收费。

## 4. 备份与恢复

采用原生 PostgreSQL + pgBackRest 的异机加密备份方案；工具是运维依赖，无 Docker 前提。可使用用户管理的 S3 兼容对象存储或受控的异机仓库，地址和凭据在部署时配置。

默认计划：每周全量、每天差异、持续 WAL 归档，保留最近 4 个周全量及其完整依赖链，形成约 28–35 天窗口；实际恢复范围由成功备份、WAL 连续性和工具保留规则确认，不能只按日历宣称可恢复。每月恢复演练一次，并在升级前校验最近可恢复点。

30GB 本机不作为完整备份仓库，不保留多份完整数据库副本。备份优先流向异机，临时导出使用受限空间；客户端安装包由下载站存储，不占数据库备份预算。

工程目标：在异机仓库、网络与归档正常且已演练的前提下，RPO 不超过 15 分钟，RTO 不超过 4 小时。这是待验证目标，不是已达到的 SLA，也不保证单机磁盘故障零损失。

候选 `archive_timeout=300s` 配合持续归档与告警验证；最近异机可恢复点落后超过 10 分钟提醒，超过 15 分钟停止新的收费执行和充值订单，仍处理已存在订单的必要核验。不得通过丢弃尚未安全归档的 WAL 假装保持备份健康。

备份密钥和平台凭据主密钥受限保存，另有受保护的恢复副本。恢复先核对 schema/密钥、停止外部副作用和新收费，重建资金余额与去重状态，再与支付平台及任务事实对账。

官方工具依据：[pgBackRest User Guide](https://pgbackrest.org/user-guide.html)。具体版本和配置实施时固定，备份完整性检查不能替代实际恢复演练。

## 5. 删除与恢复后的防复活

用户删除请求立即撤销执行授权，清理有效登录与平台会话使用权。处理未结算余额、争议及法定保留后，删除或匿名化不需保留的数据。

删除/撤销标记在恢复时重新应用，防止旧备份重新启用已撤销授权或让已删除题图进入前台。保留备份到期说明，限制备份只用于恢复，不用于分析或重新查询模型。

异机备份目标尚未提供，因此当前不能宣称 RPO/RTO 已满足；它是部署配置项，不再要求用户重新设计保留策略。
