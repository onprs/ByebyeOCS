# 数据保留、隐私闭户与容灾备份架构

> **适用范围**：开发维护与生产合规运维规范，对应 `server/internal/operations`、`server/internal/auth/erase.go`、`services/tiku/internal/platform/store` 及 `deploy/backup.sh`。

## 1. 分层数据保留周期（TTL）

面向约 `30GB` 单机磁盘预算与最小化个人信息留存原则，系统将运行过程数据与法定不可变财务/审计证据严格分层，每日低峰按每批最多 `500` 行（单次作业限时 `30s`）渐进清理并交由 PostgreSQL `autovacuum` 回收空间：

| 数据类别 | 默认保留期限 | 到期处理行为 |
| --- | --- | --- |
| 短期登录挑战与已过期会话令牌 | 即时 / 7 天内 | 自动清理过期挑战与已失效会话记录 |
| SSE 投递流条目（`event_stream_entries`） | `3 天` | 删除过期序号条目，滞后游标重连时下发 `resync_required` |
| 已发布事务 Outbox（`learning_outbox`） | `7 天` | 仅清理 `published_at IS NOT NULL` 的历史桥接行 |
| 题库精确缓存与查询答案原文 | 默认 `7 天`（按条目策略最高 `30 天`） | 题库库物理清除过期缓存，清空 `tiku.queries` 与 `requests` 中的题目/答案大载荷（题图绝不落盘），**永久保留幂等键摘要与 token 汇总防重复调用**；主库同步为已结清查询打上内容过期标记 |
| 题库单次模型调用明细（`tiku.model_calls`） | `30 天` | 清理槽位级过程明细，保留查询级汇总账据 |
| 个人数据加密导出归档文件 | 短期有效（默认 `24 小时` 内） | 到期自动删除磁盘密文文件并失效下载链接 |
| 题库维护面板审计（`tiku.panel_audit`） | `180 天` | 分批滚动清理超期面板维护记录 |
| 复式账本、充值/退款订单、有效任务点结算凭证、主库关键审计 | **不设自动删除 TTL** | 长期保留脱敏业务编号、整数金额、微元价格快照与核验事实；关联用户闭户时剥离个人身份信息 |

## 2. 受控数据导出与防复活隐私闭户（迁移 15）

### 2.1 有界个人数据导出

用户在个人设置发起数据导出时，系统生成不超过 `operations.export_max_bytes`（默认 `8 MiB`，上限 `32 MiB`）的个人业务快照（涵盖档案摘要、课程与安排概况、任务记录、订单与账本流水，**严格排除密码哈希、平台会话密文、CSRF/刷新令牌与内部密钥**），经应用主密钥加密落盘，仅允许发起导出的本人会话在有效期内流式下载。

### 2.2 账号删除申请与恢复防复活

1. **即时冻结外部副作用**：用户通过近期身份核验提交账号删除申请后，系统在同一事务内立即吊销其全部 Web/原生登录会话与学习通 `platform_sessions` 凭据，暂停名下所有学习安排并向在途任务发出停止信号，随后返回受理回执。
2. **财务与运行结清核查**：若账户仍存在在途未决充值订单、未释放冻结预占或待处理争议退款，申请保持待复核状态；管理员在后台 `/privacy-requests` 核实结清后批准闭户（若驳回申请，用户既有平台授权仍保持吊销，须重新登录验证）。
3. **脱敏匿名化与 `reapply_privacy_closures`**：完成闭户时，系统清除用户的外部主体密文、姓名、学校、偏好与课程个人会话数据，将用户行匿名化，同时保留不可变账本分录与去重标记，并将该内部用户 UUID 记入 `privacy_closures`。当从早于闭户时刻的历史备份恢复数据库时，执行 `SELECT public.reapply_privacy_closures(...)` 即可幂等重放闭户脱敏，严防已注销用户的平台凭据从旧备份中“复活”。

## 3. 磁盘三级水位熔断与异机备份门控

### 3.1 磁盘空间三级保护（`operations.disk_protection`）

- **`>= 70%`（预警级）**：管理端运行总览与健康摘要亮起黄色磁盘告警，提示运维人员检查日志与暂存目录。
- **`>= 80%`（保护级）**：自动拒绝创建新充值订单、发起新学习任务执行、提交新题库查询及生成新数据导出，保留已有任务收敛与回调入账空间。
- **`>= 90%`（维护级）**：进入严格保护模式，仅放行必要的预占释放、会话登出与管理端维护查询；任何情况下系统均不会删除账本分录或 PostgreSQL WAL 文件来换取磁盘空间。

### 3.2 一致性逻辑加密备份与持续 WAL 演进

- **当前内置交付（`deploy/backup.sh` + `restore-drill.sh`）**：通过 `pg_dump --format=custom` 分别获取主库与题库库的一致性快照，连同两套服务的配置文件及完整解密 keyring 打包后使用 `age` 公钥流式加密，上传至异机 SSH 目标并校验远端 SHA-256 一致后才原子更新 `backup-status.json`。主服务在开启收款或扣费时强制校验 `backup_max_age <= 15m`，备份落后超过 15 分钟即自动熔断新充值与新扣费。
- **大规模生产演进（`pgBackRest` 持续 WAL）**：当单库体积增长至定期全量 `pg_dump` 无法在 15 分钟窗口内完成异机传输时，生产环境可平滑切换为原生 PostgreSQL + `pgBackRest` 异机加密仓库（每周全量 + 每日差异 + 持续 WAL 归档，目标 `RPO <= 15m`、`RTO <= 4h`，实际指标须以部署目标现场演练为准）。
