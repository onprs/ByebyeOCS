# 安全、验证、监控与准入

本节记录已核查的外部事实、设计要求和仍未确认事项。没有真实后端、安全审计、商户联调或商店审核结果。

## 1. 上线门槛

| 事项 | 已核查事实 | 当前结论 |
| --- | --- | --- |
| 平台条款 | 超星同域公开用户协议涉及凭据出借、第三方信息使用与材料商业使用；模板含产品名空缺和旧法引用 | 不能当作当前账号最终适用合同；需核对实际登录路径、学校约定及书面授权 |
| 登录授权 | 有研究用密码登录工具，未确认第三方 SaaS 可用的官方 OAuth/扫码授权 | 保留候选交互，真实连接未获上线授权 |
| 学习记录 | 特定课程可出现无真实播放却平台标为通过的观察 | 不宣称真实观看，不推广到所有课程 |
| 商户准入 | zpayz.cn 公开商户协议涉及实际经营业务、禁限售类别、实名及交易争议义务 | 提供商已确认，真实商户配置和业务类别仍待核对；不能直接开启收款 |
| 商店支付 | Apple/Google 对数字服务付款有平台要求与地区/项目例外 | 必须按实际分发渠道核对，不默认 H5 ZPay 通用 |
| 隐私 | 中国个人信息保护法有最小必要、告知、委托/对外提供、敏感信息和跨境规则 | 需明确 SaaS、题库、模型服务与支付方角色、数据流和必要法律基础 |

平台公开协议的 1.4 条涉及未事先书面同意的凭据出借，6.2 条涉及材料的商业使用。它们提示本产品需要核定授权范围；不能仅据公开模板断言所有自动化都合法或都违法。此前带 `appId=1000117` 的规范动态页面实际属于其他校园产品，已排除，不作为学习通协议证据。

商业功能在对应门槛完成前保持关闭；可以继续做合同、只读模拟和经过授权的测试，不用规避计时、身份验证或平台限制来填补授权空缺。

## 2. Apple 与 Google 数字服务支付

已读取 Apple App Review Guidelines 3.1.1、3.1.3 及 Google Play Payments 政策。

- Apple 一般要求在 App 内解锁数字功能/服务使用 IAP；其当前文字对美国 storefront 的外部购买链接和部分地区 entitlement 有具体例外，不能套用旧的一刀切结论。
- 3.1.3 中跨平台、特定服务或免费伴随应用有各自条件；“学习管理”名称本身不自动构成例外。
- Google Play 一般要求数字服务使用 Play 结算，符合地区/项目要求的替代结算和外链另有规则；不得仅放一个 WebView 收银台就认为满足要求。
- 所购积分、退款、跨渠道余额和数字权益需要与实际渠道规则一致。若做 IAP/Play Billing，必须有服务端交易核验和退款通知，不让 App 自报成功。

首期采用 Flutter Web，后续 App 放在自有下载站。Android 可发布签名 APK；iOS 网站分发有适用地区、开发者资格与签名条件，企业计划仅针对内部员工。下载站不能替代这些条件，详见 [分发设计](distribution.md)。

## 3. 隐私与数据最小化

依据本轮已读的网信办转载《个人信息保护法》全文，设计至少覆盖：

- 第 6、17、19 条：目的、最小必要、清楚告知和最短必要保存。
- 第 21、23 条：委托处理与向独立处理者提供的不同责任；根据关系确定合同、告知和所需单独同意，不能用笼统登录勾选覆盖所有第三方。
- 第 28–31 条：可能涉及金融账户、身份或未成年人等信息时，评估敏感性、必要性和专门保护；不默认所有学生都成年。
- 第 38、39 条及相关现行配套规定：题目、图片或身份经境外模型/服务处理时，核对跨境路径和适用机制；不能仅凭服务器在国内就认定没有跨境。
- 第 44–47、51、55 条：访问复制、更正删除、安全措施及适用场景的影响评估。

不采集人脸、定位、通讯录等与本平台核心功能无关的权限。确需官方身份挑战时交由平台支持的流程处理，不托管额外生物信息。

课程和题目最少化上传，去除无关身份信息；第三方模型目的、留存与训练使用须核对。删除申请对依法需保留的数据停止其他处理并限制访问，不能一键删除资金审计后声称满足全部义务。

题目、选项和图片可能经 fork 转交上游模型服务。隐私说明需列出实际模型提供商、处理目的、保留和是否用于训练；用户选择公开模型不等于授权所有上游服务。共享缓存会扩大题目复用范围，默认关闭，开启前单独评估。

## 4. 安全边界

| 威胁 | 主要控制 |
| --- | --- |
| 跨用户任务/余额访问 | 主体上下文、资源归属、复合约束与反向 ID 测试 |
| 管理员越权/内部滥用 | 独立认证、专用权限、提升验证、理由、审计和可撤销会话 |
| 凭据泄漏 | 不保存原密码、Cookie 认证加密、秘密引用、日志/错误/追踪脱敏 |
| CSRF/XSS/会话窃取 | 同源 Cookie、Origin/CSRF 检查、CSP、内容转义、不把令牌放 URL |
| SSRF/恶意附件 | 目标及跳转校验、解析后地址限制、体积/时间/像素上限，OCS 管理地址仅由授权管理员配置 |
| 重复通知/并发扣费 | Inbox、业务唯一键、锁和原子账本、重建对账 |
| 未知外部执行结果 | 任务独占、停止旧实例、恢复核验，不盲目重放 |
| 模型越权/密钥泄漏 | 用户只能选公开条目；上游模型名和密钥只存 fork 受保护配置；服务间认证与私网 |
| 缓存污染/跨用户泄漏 | 仅精确匹配、成功答案可写入；默认用户作用域；共享缓存显式开启；错误报告与失效 |
| token 用量伪造/缺失 | 只信服务端 fork 响应；字段边界与 complete 校验；同一 request_id 幂等；定期账单核对 |
| fork 供应链/升级回归 | 固定 upstream 版本、保留测试、独立模块；更新前比对 API/行为；依赖许可审查 |
| 供应链与更新 | 固定依赖、可重复构建、签名校验、schema 兼容和受控主机权限 |
| 数据恢复不完整 | 加密备份、密钥分离、演练、冻结新收费后核验 |

本机 pprof、完整堆转储、原始上游响应和秘密配置不通过普通管理页面公开。调试入口只在明确维护模式、受保护访问下使用，保留审计。

## 5. 测试分层

1. 领域不变量：任务状态转移、安排版本、规范任务去重、价格快照与预占/结算/释放的模型测试。
2. 资金性质测试：随机操作序列后每笔 journal 平衡、可用余额非负、缓存等于重建；重复通知、并发扣费与部分失败无第二笔记账。
3. PostgreSQL 集成契约：覆盖归属、幂等、锁冲突、迁移与恢复场景，使用与目标部署一致的 PostgreSQL 主版本和原生测试实例，无 Docker 前提。
4. Adapter 固定样本：已脱敏课程与任务字段、图片题、题型和错误；提供商签名黄金向量，不基于猜测编造字段。
5. 题库 fork 契约：模型目录可见性、禁用模型、图片/视觉降级、精确缓存命中与模糊候选隔离、缓存失效/报告、token 分解、幂等重放和 `usage_incomplete`；PostgreSQL 独立库迁移与恢复。
6. 故障注入：外部请求前后、支付 Inbox 保存后、资金提交前后、事件发布前后杀进程；旧实例未停止时禁止新副作用。
7. API/客户端：越权、CSRF、幂等请求、版本冲突、SSE 缺口/乱序、支付回跳、App 后台和升级兼容。
8. 真实平台小规模验收：明确授权账号和任务，停止验证码/403/429 等异常；记录具体适用课程，不扩大结论。

## 6. 资源与负载验证

以用户指定的约 2C4G / 30GB 为目标，参考既有研究但重新测量 SaaS 的数据库、SSE、运营查询和支付开销，遵循 [容量基线](capacity.md)。以任务数、请求率、活跃连接和检查点频率构造矩阵，不只报告账号数。

独立测量内存、CPU、goroutine、FD、HTTP 连接、数据库锁等待、写事务 P95/P99、队列等待、核验延迟、支付 Inbox 与到账延迟。先用可控平台模拟器评估本地调度能力，再以授权的小规模实验评估外部平台限制。

任何压测达到的数字只适用于指定硬件、版本和场景；不能用合成 Dashboard 的值作为并发、可用性或收入数据。

## 7. 监控、日志与告警

- 状态：活跃/过期租约、执行与等待验证、人工处理、控制未确认、队列年龄。
- 账务：已付未到账、通知处理积压、重复交易、账本不平、余额缓存差异、退款待查。
- 服务：API 时延/错误率、OCS 可达性与功能失败、模型目录健康、缓存命中率、token 用量/缺失、上游限流、资源与磁盘/WAL。
- 题库：查询成功率、精确缓存命中/失效、共享缓存开关、每次查询 token 分布、`usage_incomplete`、上游账单差异和 fork 版本。
- 运维：备份时效、恢复演练、版本/schema 兼容、密钥轮换与异常管理登录。

指标标签不放用户 ID、姓名、完整课程或任务 ID，避免泄露与高基数。详细追踪仅在受权限控制的任务页和脱敏日志中查阅。资金不变量失败立即冻结相关操作；一般资源阈值需在试点测量后确定。

当前主服务和独立题库已完成竞态及隔离PostgreSQL集成检查，React/Flutter有构建和真实本地API交互记录；任务确认/账本、题库token/账本及隐私复核有组合测试。逐项证据见 [当前实现](../development/local-implementation.md)。真实外部平台、付款、模型、生产恢复、容量及分发仍未验收，不能把本地夹具通过推广为外部成功。
