# 课程同步与共享资源目录缓存架构

> **适用范围**：正式 Go 主服务（`server/internal/learning`）与 Flutter 用户端（`apps/client_flutter/`）的课程同步编排、并发节奏自适应与跨用户目录缓存规范。

## 1. 两阶段同步编排与容错边界

1. **自动触发与唯一内联提示**：用户进入首页或课程列表页时自动触发或接续已有同步请求（距上次成功不足 6 小时不重复自动发起，手动刷新不受限）。前端通过全局 `CourseSyncController` 维护唯一内联进度条，用户关闭某次结果提示后，同一同步记录在页面轮询或路由切换时不再重现。
2. **第一阶段（完整概要发布）**：在单次同步隔离 Cookie 容器内读取课程列表，按课程容器配对提取课程名、教师、封面地址及 `not-open-tip` 已结束课程标记（写入 `learning_courses.platform_state`），批量落库概要使全部课程卡片立即可见；首次建档尚未拉取章节的课程 `snapshot_version` 为 `0`。
3. **第二阶段（逐课完整快照提交）**：由 2 个课程同步消费者协程并发推进，单门课程内按 `ChapterConcurrency`（默认 `4`，上限 `64`）并发读取开放章节。长课程写入快照期间不长时间独占同步任务行锁，允许心跳持续续租。
4. **旧快照保护与断点续传**：
   - 仅当整门课程章节树与卡片全部解析校验通过后，才按有界批次事务原子递增 `snapshot_version` 提交新快照；若某门课程遭遇结构异常或瞬态失败，**完整保留该课上一次有效快照与绑定任务**，同步整体记为部分完成并继续处理其余课程。
   - 重试或最近 6 小时内再次发起同步时，自动跳过已由当前适配版本完整提交的课程，避免整批重读。
   - 确认归属当前课程的“暂无章节内容”页面及空初始化 `$mArg` 模板按合法空目录/空章节入库；损坏 JSON 或越权页面明确报错拦截。

## 2. 跨用户共享页码目录缓存与结构指纹优化

### 2.1 24 小时共享卡片页码目录缓存（迁移 25）

学习通读取小节详情通常需先请求 `studentstudyAjax` 枚举卡片页码，再按页码读取具体卡片。系统将**不含个人数据的章节卡片页码目录**提取为跨用户共享缓存：

- **缓存键与隔离边界**：对 `(适配版本, 结构版本, 固定上游入口, course_id, clazz_id, cpi_scope/周期, chapter_id)` 计算 SHA-256。个人完成度、历史播放秒数、Cookie 与用户身份**绝不进入共享缓存**；每次读取前先通过当前用户会话验证该用户确有该课程与章节的访问归属。
- **双层存储与并发合并**：进程内 LRU 最多保留 `4,096` 条，同时持久化至主库 `learning_resource_cache`，有效期 `24 小时`（过期记录随每日每批 `500` 行的维护任务清理）。同一目录键并发未命中时通过 `singleflight` 合并回源；若首个回源因发起者个人会话异常失败，不向其他等待者广播错误，由等待者使用自身会话独立回源。

### 2.2 课程结构指纹减半冷同步请求（迁移 28）

冷同步或缓存过期重读时，适配器提取课程目录页面的章节结构指纹提示（`course_structure_hint`）。当章节树拓扑与已知单页/多页分布指纹吻合时，直接复用已核实的章节页码分布跳过冗余探测请求，在保证完整发现的前提下将冷同步上游请求量降低约一半。

## 3. 自适应上游请求节奏控制

同一平台实例下的相邻上游 HTTP 请求受动态令牌桶节流保护，参数支持 `owner` 在管理端“系统设置 → 运行安全”在线热更新：

- **基准间隔与提速下限**：`learning.request_interval` 默认 `300ms`（合法范围 `50ms–2s`）；`learning.request_interval_floor` 定义自适应提速下限（合法范围 `10ms–request_interval`，设为 `0` 时自动取 `request_interval` 的一半）。
- **平滑提速与退避恢复**：连续 `50` 次上游请求成功后，当前间隔自动缩短 `10%` 直至触达 `request_interval_floor`；一旦收到上游 `429`、网关瞬态错误或限流信号，立即回退放大请求间隔并遵守 `Retry-After`，兼顾大课程同步吞吐与上游友好性。
