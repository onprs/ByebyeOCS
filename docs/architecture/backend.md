# Go 服务端设计

## 工程边界

正式主服务位于独立 `server/` 模块，独立题库位于 `services/tiku/`。身份、学习、账务/支付、题库编排、事件、隐私与维护模块均已实现；当前路径与验证见 [本地实现](../development/local-implementation.md)。下文保留模块化单体的职责设计，实际调用以源码与OpenAPI为准。

```text
cmd/byebyeocs/                  # serve、migrate、doctor、backup 等命令
internal/command/              # 维护命令与安全输出
internal/app/                  # 依赖装配、双端监听与生命周期
internal/platform/config/      # 严格配置、环境覆盖与受保护连接文件
internal/platform/fault/       # 安全错误码，不携带原始异常
internal/identity/             # 外部身份、内部用户、执行授权与会话
internal/admin/                # 管理员认证、权限、审计
internal/catalog/              # 课程快照、章节、任务点
internal/plans/                # 不可变安排版本、任务生成
internal/scheduler/            # 公平领取、租约、独占和恢复
internal/execution/            # 有界执行池、检查点与证据
internal/verification/         # 新鲜平台查询与结果判定
internal/questions/            # Provider 接口、答案与确认
internal/wallet/               # 价格快照、预占、账本与退款资金
internal/payments/             # 下单、通知、查单与对账
internal/events/               # Outbox、持久化投递流与 SSE
internal/adapters/chaoxing/     # 原生平台 HTTP 适配
internal/adapters/ocstiku/      # 独立题库服务适配
internal/adapters/zpay/         # 固定提供商与协议版本的适配
internal/platform/postgres/    # PostgreSQL 访问、连接池、内置迁移与显式事务
internal/transport/httpapi/     # 用户和管理员独立路由、OpenAPI
internal/operations/           # 健康、指标、备份和升级协调
web/                           # 两套独立前端产物及可选 Flutter Web 资源
internal/platform/postgres/migrations/ # 内嵌 PostgreSQL 版本化 SQL
```

不建立通用 RPC、事件总线框架或每模块微服务。采用构造器注入、明确依赖和小接口，避免全局数据库与全局当前用户。

## 应用服务和事务

请求先完成认证、资源归属、幂等键及版本校验，再进入应用服务。Repository 不自行开启隐式跨模块事务；`UnitOfWork` 把同一数据库事务提供给需要共同提交的模块。

典型事务边界：

- 安排保存：检查版本 → 新建不可变版本 → 更新安排指针 → 审计 → Outbox。
- 任务领取：核对控制版本、账号状态和额度 → 独占记录 → 新执行尝试与租约 → 任务准备状态 → Outbox。
- 收费准备：检查价格版本和余额 → 同一任务收费业务的预占 → 关联尝试。网络请求在事务之外。
- 结算：核验平台结果 → 标记任务确认 → 按收费业务唯一键结算/释放 → 审计 → Outbox。
- 充值：锁定订单和钱包 → 核对已查明的渠道事实 → 唯一入账 → 订单到账标记 → Outbox。

平台调用、题库请求和支付网络调用都不得持有数据库写锁。调用前后用版本/尝试号关联；状态发生冲突时重新检查，不能把旧结果覆盖到新安排或新身份。

## HTTP 与资源控制

- 用户 API 与管理员 API 使用不同路由树和认证中间件；默认两个回环监听入口，反向代理按域名转发。
- 共享连接池，按账号隔离 Cookie Jar；不能在共用 Transport 上串改账号 Cookie。
- 对目标域名、跳转、下载体积、超时和每账号请求速率施加限制；平台资源链接也视为不可信输入。
- 学习请求、平台核验、题库、课程同步、支付查单使用独立有界池；支付与账务不等待媒体任务队列。
- 配额分为内存执行名额、账号名额、平台请求速率和题库名额，不把 HTTP 连接数等同于任务并发。
- 空闲任务只存数据库，不为每个排队任务创建 goroutine。运行、SSE 和后台扫描各有数量上限。
- 检查点合并落库，例如状态变化立即写、过程观察按可配置间隔合并；不为每秒 UI 刷新写一条账本或任务记录。

按约 2C4G / 30GB 的初始资源预算，全局 4、账号 1、题库 2 为待压测的保守配置，不代表平台允许能力，详见 [容量基线](capacity.md)。允许经授权验证后提升账号并发；架构没有账号级全程串行锁。原型中的 16/2 是合成展示值，不是正式容量承诺。

## 配置与秘密

优先级：内建安全默认值 < 配置文件 < 带项目前缀的环境变量 < 显式命令行参数。缺失生产秘密、未知提供商或不一致的币种配置启动失败，不能悄悄回落到演示支付。

秘密使用受限文件引用或部署环境注入。命令行支持普通配置覆盖，但不推荐把商户密钥、密码或数据库口令作为参数暴露在进程列表。诊断输出仅显示来源和是否配置，不输出值。

运行时热修改限定为明确白名单：名额上限、通知和非敏感展示配置。密钥轮换、数据库地址、授权模式和 schema 变更采用校验后重启或专用操作；记录配置版本与审计。

## 生命周期

启动顺序：读取校验配置 → 打开数据库与 schema 兼容检查 → 载入密钥 → 注册适配器能力 → 恢复扫描 → 健康就绪 → 开启新任务领取。

关闭顺序：停止接收新调度 → API 对写请求进入维护状态 → 向 SSE 发出重连提示 → 通知执行器安全停止 → 写入检查点及控制确认 → 停止外部请求 → 提交账务和事件 → 关闭连接。

超时后终止的尝试标为结果待核验，下一次启动先查平台再决定是否重新执行。未投递的 Outbox 和支付 Inbox 均可恢复，不依赖进程退出前成功清空内存。

## 错误模型

错误包含内部分类、可重试性、影响范围、用户可读原因和关联编号。日志保存结构化错误码，不直接记录上游响应、凭据或签名 URL。

| 类别 | 行为 |
| --- | --- |
| 超时/短暂连接失败 | 有界退避；有副作用时先核验结果 |
| 验证码/身份过期 | 冻结相关执行授权，交由持有人重新验证 |
| 403/权限异常 | 停止相关范围，禁止自动绕过 |
| 429/平台限流 | 停止相关操作并提示；不得按普通网络错误无限重试 |
| 课程或资源失效 | 标记需要处理或失败，保留证据与收费结果 |
| 余额不足 | 不领取新的付费任务，通知用户 |
| 任务/安排版本冲突 | 返回明确冲突，不覆盖新版本 |
| 数据库异常或租约失联 | 停止外部副作用；恢复后查明状态 |

日志、指标、测试与故障注入要求见 [验证设计](security-and-validation.md)。
