# 身份、会话与资金归属

## 身份主体

普通用户仍直接使用学习通身份，不建立需要用户注册的第二套账号。内部用户是数据库和账务主体，与学习通用户名、学校展示名称和管理员账号分离。

```text
内部用户 1 ── N 外部身份关联记录（MVP 仅开放一个有效学习通主体）
外部身份 1 ── N 平台会话 / 授权记录
内部用户 1 ── N 客户端登录会话
管理员   1 ── N 独立管理员会话
```

稳定主体必须由服务端通过学习通的可信会话查询确认。候选 UID 的全局/学校命名空间、变更规则和会话一致性尚需验证；不能只读取客户端传入的 UID、Cookie 内自述字段或用户名。

外部身份键使用明确命名空间和已验证主体，数据库加唯一约束。使用加密主体值与HMAC查询索引；独立长期身份索引密钥在加密主密钥正常轮换时保持不变。索引密钥迁移需要另行设计现有主体和闭户防复活标记的连续性，当前不提供直接轮换该密钥的命令。

## 登录方式与合法授权

| 方式 | 设计 | 当前事实与门槛 |
| --- | --- | --- |
| 官方授权/受支持扫码 | 官方挑战 → 持有人确认 → 服务端验证会话 | 尚未发现可直接认定适用于第三方 SaaS 的官方 OAuth；原型扫码是候选 |
| 账号密码 | TLS 内一次性接收、正常完成官方验证、建立会话 | 已有研究登录工具，不等于获准商业使用；正式启用前核对授权与条款 |
| 验证码/交互验证 | 挑战绑定本次登录，由持有人完成 | 不自动识别或绕过，不向其他用户转交验证 |
| 重新验证 | 新会话验证相同主体，再替换旧会话 | 不接受只提交新用户名就覆盖资金主体 |

本轮已读取超星公开用户协议模板，并排除了其他校园产品的协议页面。模板的适用产品和当前版本仍需核定；其中账号使用和材料商业使用等条款需要平台/学校授权与法律评估，普通登录成功不等于有权提供商业自动化。正式平台连接默认关闭，满足授权门槛后启用对应适配器能力。详见 [准入与来源](security-and-validation.md)。

MVP 的目标仍是无额外注册的身份登录，授权未解决时提供模拟或只读演示，不用未经确认的登录绕过替代。

## 首次与重复登录

服务端在短事务中按稳定主体查找或建立内部用户，插入有效身份关联，再签发本平台会话。两个并发首次登录依靠唯一键收敛到同一用户；失败事务不会留下两个钱包。

课程同步异步启动，登录不等待所有课程完成。身份、平台会话和课程同步状态分别反馈，部分课程无权限不抹掉已有订单与余额。

## 凭据保存

- 原始密码默认不持久化；验证结束后从请求上下文释放，不加入日志、追踪、错误或审计。Go 内存不承诺所有副本可被可靠清零，因此仍需最小生命周期和受控诊断。
- 平台 Cookie 与续期所需敏感状态使用 AES-GCM 等认证加密：随机 nonce、密钥版本、主体/记录 ID 作为关联数据，主密钥放在受限文件或受控密钥服务中。
- 数据库中存密文、到期时间和版本。管理员只能查看会话状态和更新摘要，不能获取解密接口或临时下载凭据。
- Cookie Jar 按账号隔离；会话轮换按版本替换，旧执行器不得回写旧 Cookie 覆盖新会话。
- 没有可靠续期协议时要求重新验证，不默认保存密码定时登录。

备份同时保护数据库和密钥，但分开保存、限制恢复权限。丢失密钥时要求重新登录，不通过关闭加密恢复服务。

## 客户端与管理员认证

Web 使用 HttpOnly、Secure、SameSite 的主机限定 Cookie；用户和管理员建议不同域名与监听入口。写操作校验 CSRF、Origin 和资源归属。管理员独立账号采用强密码哈希与第二因素，不依赖任一学习通身份获得权限。

App 使用短期访问令牌与轮换刷新令牌；刷新令牌保存在系统安全存储，服务器只保存不可逆摘要和撤销链。刷新令牌复用视为风险，撤销该会话链。时间策略是可配置设计参数，实施阶段固定并测试。

SSE 的 Web 认证使用同源 Cookie；不得把访问令牌放 URL。Flutter App 可以使用带认证头的流请求。

内部客户端会话和外部平台会话分别失效：外部失效停止学习操作并提示重新验证，仍可在有效的本平台会话中查看余额和历史。支付或数据删除等敏感操作要求新鲜身份验证。

## 执行授权与退出

安排创建时记录用户明确授权的能力、课程范围、隐私版本和时间。扩大任务范围或新增测验提交能力需要新的确认，不能因为旧授权存在就无限扩大。

退出当前客户端默认撤销本客户端会话；持续运行的安排仅在用户已明确授权云端执行且界面清楚说明时继续。另提供“停止所有安排并撤销执行授权”。撤销立即阻断新任务，当前尝试按安全停止流程处理。

## 账号变化、申诉与余额

| 情况 | 处理 |
| --- | --- |
| 忘记密码 | 使用学习通/学校官方找回；本平台不重置学习通密码 |
| 用户名或学校展示变更 | 稳定主体未变，保留内部用户和账务归属 |
| 主体变更或重复绑定 | 暂停迁移，核验旧/新身份及订单，不自动合并钱包 |
| 外部账号被盗或学校回收 | 冻结敏感资金操作和执行授权，进入人工申诉 |
| 用户要求转余额 | MVP 不支持用户间转账，身份更正走受审计的内部迁移流程 |
| 导出/删除 | 新鲜身份校验，导出不含凭据；删除前处理安排与未结算资金 |

申诉材料最小化，不收集完整密码、Cookie 或支付密码。人工迁移需要独立权限、原因、关联材料及复核，保留原账本链路，不能直接改充值订单的用户 ID。
