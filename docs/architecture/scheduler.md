# 任务调度与执行状态机架构

> **适用范围**：开发维护环境，说明 `server/internal/learning` 中持久化公平调度、单任务租约与 fencing、执行前新鲜核验、冷却恢复及在途停止握手的实现机制。

## 1. 稳定任务键与两级并发配额

研究阶段的批量脚本曾使用“整账号互斥锁”，无法满足同一用户多门课程并行推进的需求。正式调度器将独占粒度收敛至**单个稳定任务键**：

- **稳定任务键构成**：`(internal_user_id, external_identity_id, course_id, clazz_id, chapter_id, job_id / attachment_identity)`。普通无 `jobid` 的学习资料附件在解析阶段即标记为非任务点，不生成待调度任务。
- **并发配额双控**：调度器同时受 `runtimeconfig` 中的全局并发槽位 `GlobalConcurrency`（默认 `4`，范围 `1–256`）与单账号并发槽位 `AccountConcurrency`（默认 `4`，不超过全局上限）约束，在多用户同时排队时按账号轮转公平分配槽位，防止单一重度账号饿死其他用户。

## 2. 数据库租约、续期与 Fencing Token

系统不依赖进程内存锁，所有执行权均通过 PostgreSQL 行锁与租约字段协调：

1. **原子领取**：调度器挑选 `state = 'pending'`、`desired_state = 'run'`、未处于冷却期、且所属用户/会话/课程/章节/任务点均正常可用的任务，通过 `FOR UPDATE SKIP LOCKED` 原子递增 `fencing_token`、写入 `lease_owner` 与 `lease_expires_at`，同时插入新一轮 `learning_task_attempts` 记录。
2. **心跳续租与控制感知**：执行协程在运行期间定期向数据库发送心跳延长 `lease_expires_at`，并在每次心跳返回中同步读取最新的 `desired_state`（是否收到暂停/取消指令）以及账号限制、章节关闭或用户闭户信号，一旦检测到停止条件立即中断后续网络请求。
3. **Fencing 写回保护**：所有观察进度更新、状态流转与结算触发语句均携带 `WHERE id = $1 AND fencing_token = $2` 条件。即使某个假死协程在租约超时被其他协程接管后苏醒，其迟到的数据库写入也会因 `fencing_token` 失配被无害拒绝。

## 3. 执行前新鲜核验与崩溃恢复

### 3.1 执行前只读复核（Pre-flight Check）

领取租约后、发起任何耗时推进或题库查询前，执行器必须先拉取最新章节卡片或测验工作页执行新鲜只读检查：

- 若平台已确认该任务点完成，直接将任务置为 `confirmed`（记录为预完成 `precompleted`），**全额释放本次安排绑定的余额预占，不重复执行，也不产生任何扣费**。
- 若发现课程已结束、章节已关闭或测验未开放/已截止，立即写入持久可用性表并将任务转入关闭状态，退出待处理队列。

### 3.2 孤立租约接管与防重放恢复

服务重启或协程异常退出遗留过期租约时，恢复器按任务在崩溃前持久化的证据分级处置：

- **已发起最终交卷的测验任务**：一旦任务已记录最终提交意图标记，无论是崩溃恢复还是用户点击“重新调度”，系统**直接进入 `verifying` 独立平台只读核验阶段**，严禁重新领取执行或再次发送最终提交请求。
- **在途题库查询任务**：沿用已持久化的查询请求 ID 与幂等键向题库核对结果，保持冻结的价格快照与预占不变。
- **瞬态网络错误与冷却恢复**：针对连接重置、网关超时或上游 `429/503`（自动遵守响应 `Retry-After` 等待时长），任务在常规尝试次数耗尽后最多允许自动进入 **2 轮冷却恢复（Cooling Down）**（迁移 34）；验证失败（验证码、`403` 权限拒绝、会话过期、字形歧义、答案无法唯一映射）则立即停止并转入 `needs_attention` 等待人工处理，绝不盲目重试。

## 4. 安排归档、改版与三级可用性联动

- **不可变安排版本**：用户编辑正在运行的安排时，服务端创建新的 `learning_plan_revisions` 版本并重新计算绑定集合；已在途运行的任务安全收敛，取消绑定的未完成任务释放对应未消费预占。删除安排执行软归档（迁移 29），对用户列表隐藏并停止后续派发，完整保留既有任务历史与账本流水。
- **重新检查可用性**：对处于 `course_closed`、章节关闭或 `quiz_closed` 状态的任务，用户点击“重新检查可用性”时，系统先触发目标课程目录刷新，若平台确已重新开放则自动恢复由关闭原因暂停的任务（已交卷任务仍仅走只读核验）。
