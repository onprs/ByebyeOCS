# 任务调度、独占与恢复

## 1. 任务身份与去重

任务主键不包含安排 ID。建议唯一范围为：平台身份命名空间 + 已验证账号主体 + 课程/班级 + 章节/知识点 + 真实任务点标识 + 已确认的课程重置周期。具体上游标识组合要在适配器契约测试中验证，不能只使用视频 URL、文件名或 `isPassed`。

多个安排可以引用同一个规范任务；用 `plan_task_bindings` 记录关联。重复创建安排不会创建第二个同任务执行或第二笔任务收费。停用一个安排仅撤销其后续调度意图；其他安排仍引用时不自动取消共享任务，界面显示影响范围。

无任务点编号的普通附件只进入资源目录。任务身份缺失或冲突时转人工处理，不用随机标识制造“新任务”。

## 2. 调度顺序

1. 持久化安排新版本，展开符合范围的未完成任务并建立关联。
2. 先检查账号授权、平台阻断、课程快照有效期和未来生效时间。
3. 按用户轮转，再按安排优先级和等待时长选任务，避免一个大账号耗尽名额。
4. 同时满足全局名额、账号名额、平台请求预算和任务独占。
5. 短事务内领取任务、创建尝试、绑定安排版本和价格快照；需要收费时完成幂等预占。
6. 事务提交后在执行池中调用适配器。失败回滚或释放领取状态，不把未提交任务交给执行器。

优先级不越过权限、任务独占和资金约束。提高名额不表示平台允许更高并发。

## 3. 锁与租约

| 范围 | 机制 | 说明 |
| --- | --- | --- |
| 应用实例 | 本机实例文件锁；PostgreSQL 额外校验唯一调度主实例 | MVP 仅支持一个调度主实例，不宣称多活 |
| 全局/账号名额 | 进程内统一分配器 + 持久化活跃尝试核对 | 账号槽位不是账号全程排他锁 |
| 稳定任务 | 数据库活跃尝试唯一约束 + 状态条件更新 | 无论多少安排引用，同一任务最多一个活跃尝试 |
| 本机副作用 | 按稳定任务键的 OS 文件锁 | 覆盖可选兼容子进程和旧尝试未退出的情况 |
| 租约 | 尝试 ID、持有者、单调 fencing token、到期时间 | 数据库写入必须匹配尝试和 token |

建议初始租约 45 秒、心跳 10 秒，均需故障注入验证后固定。数据库不可写或续租失败时立即停止新的外部副作用，不能仅在租约过期后重启一个相同任务。

**限制：学习通不会替本系统验证 fencing token。** 数据库租约只能阻止旧执行器写本地状态，不能撤回已经发出的 HTTP 请求。旧进程仍存活且无法确认停止时，不向新尝试授予副作用权限。必须等待进程退出、文件锁释放或管理员确认。未来跨节点执行不能直接沿用此锁模型。

## 4. 状态与证据

| 状态 | 进入条件 | 后续动作 |
| --- | --- | --- |
| 待执行 | 有有效安排、未确认、可领取 | 等待名额与权限 |
| 准备中 | 已领取并持有尝试，检查会话、资源与预占 | 进入执行或转处理 |
| 执行中 | 授权和必要能力满足 | 有界执行，保存观察与检查点 |
| 等待验证 | 执行结束或中断后结果不明 | 读取新鲜平台状态 |
| 平台已确认 | 适配器返回明确通过事实与查询时间 | 保留证据，幂等结算 |
| 已暂停 | 安全中断已被执行器确认 | 保留检查点，等待用户继续 |
| 需要人工处理 | 身份、验证码、权限、限流或能力不确定 | 停止相关操作，禁止自动绕过 |
| 失败 | 已分类为不可恢复或重试耗尽 | 人工复核或重新调度 |
| 已取消 | 取消请求已安全停止后续执行 | 保留外部事实与资金处理记录 |

`desired_state` 与实际状态独立。暂停/取消接口先返回“请求已接受”，执行器确认后才显示真正停止；过程可显示“等待安全停止”。已确认任务不回退重试。

证据字段独立：执行器位置/时长观察、平台查询事实、真实媒体记录。执行进度 100% 不自动进入平台确认。没有真实播放证据就展示无记录。

## 5. 安排修改与双端竞争

安排使用不可变 `plan_revision`。保存时 `If-Match` 校验当前版本；用户和管理员均走同一应用服务。冲突返回 412，要求重新加载后合并。

已领取尝试绑定旧版本，内容修改只影响尚未开始的任务。启停更新后续领取资格；用户可另行请求停止正在运行的任务。管理员批量操作返回逐项结果和版本冲突，不一次覆盖所有状态。

取消执行不抹掉平台已经发生的变化。如果取消后平台查询才返回通过，保留“执行已取消”和“平台后来确认”的独立事实；资金如何处理按绑定的计费规则复核，不能因本地取消直接释放已经实际消费的费用。

## 6. 核验与重试

核验使用独立轻量池；等待核验的任务释放执行名额，但保留禁止重新执行的状态。核验请求仍受账号和平台请求预算约束。

短暂只读查询失败可以限次退避。涉及外部副作用的超时先查平台，不盲目重放。403、429、验证码、登录过期和权限异常停止相关范围并通知用户；429 不作为普通网络错误持续重试。

核验长期不明的任务进入人工处理，保留资金预占与清楚的期限/原因。释放预占需在核验屏障下执行，避免“先退款，旧执行器再成功”的竞态；超过产品承诺时限的争议需要人工处置，不能无限冻结。

## 7. 服务重启恢复

1. 取得实例所有权，确认旧进程和兼容子进程没有继续产生副作用。
2. 扫描未结束尝试、待验证任务、控制请求和资金预占。
3. 对执行中/准备中且结果不明的尝试转恢复核验，先读取新鲜平台状态。
4. 已通过：记录确认事实，按唯一收费键结算一次。
5. 未通过且会话有效：根据已验证的恢复能力重新安排；不回放未核实的旧请求序列。
6. 身份失效或行为不确定：转人工处理，停止新副作用。
7. 恢复 Inbox、Outbox、待到账订单和核验扫描后再开放新任务领取。

“任务恢复”不等于精确恢复外部平台的所有会话细节，也不能承诺任意任务都可无损续跑。

## 8. 必须通过的故障场景

- 同账号四个不同任务可以受控并发，同任务重复领取始终只有一个副作用执行者。
- 杀进程发生在领取前后、外部请求返回前后、确认提交前后，均不会重复收费。
- 租约失联但旧进程仍在时，不启动第二个副作用实例。
- 暂停与完成同时发生，保留事实并按明确规则结算。
- 多安排引用、用户和管理员同时修改、重试和延迟确认不产生第二个规范任务。
- 限流、验证、资源失效和余额不足不进入无限重试。

测试使用可控 Adapter 和故障注入，真实平台实验只使用明确授权的测试身份与可接受任务，不扩大既有实验结论。
