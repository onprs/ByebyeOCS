# 产品需求与本轮范围

项目的持续对齐入口为根目录 [DESIGN.md](../../DESIGN.md)。本文补充可验收的需求拆分。

## 定位

ByebyeOCS 为学习通用户组织课程、任务安排和可信进度，为运营方提供多用户调度、服务状态和财务管理。用户端强调易用，管理端强调运营判断与批量效率。

整体UI已确认，默认石墨并保留三种配色。当前源码包括Go/PostgreSQL完整业务服务、独立题库、React管理端与Flutter Web/Android/iOS工程；本地验证及外部启用条件见 [当前实现](../development/local-implementation.md)。真实平台、付款、模型和发布签名均按独立门槛启用。

## 身份与数据归属

| 主体 | 作用 | 约束 |
| --- | --- | --- |
| 学习通账号 | 外部课程与身份来源 | 不以用户名作为稳定唯一标识；授权方式需核实 |
| 内部用户 | 余额、订单、安排与历史的归属 | 首次身份验证后自动关联，不需要用户注册第二套账号 |
| 管理员 | 独立运营身份 | 独立认证和权限，不直接查看用户原始凭据 |

MVP 已确定一个学习通主体对应一个内部用户和钱包，不开放普通用户跨身份聚合。管理端可管理不同用户的账号；账号转移、重复绑定与余额申诉进入人工核验流程。

## 用户核心需求

| 编号 | 需求 | 交互说明 |
| --- | --- | --- |
| U01 | 直接使用学习通身份进入 | 密码验证、授权说明、验证码和过期场景；扫码需要实际官方接入 |
| U02 | 快速知道当前要处理什么 | 首页课程摘要、运行安排、余额和异常入口 |
| U03 | 识别真实任务点 | 课程与章节树中区分任务点和普通学习资料 |
| U04 | 统一安排与查看实时状态 | 独立任务安排页：多课程、范围、类型、优先级、启停和任务历史 |
| U05 | 可信的完成反馈 | 执行观察、平台确认与真实媒体记录分别呈现 |
| U06 | 清楚理解充值与消费 | 金额、支付方式、付款和到账两个阶段、流水与说明 |
| U07 | 管理个人偏好和隐私 | 会话、通知、主题、导出与删除申请 |
| U08 | 选择管理员发布的答题模型 | 安排中的模型选择、能力提示和下架提示 |
| U09 | 选择缓存优先或每次模型作答 | 精确缓存命中显示、token 用量和费用说明 |

## 管理员核心需求

| 编号 | 需求 | 原型表现 |
| --- | --- | --- |
| A01 | 判断系统是否健康 | 趋势、资源、Worker、服务状态、异常摘要与实时事件 |
| A02 | 高效率处理账号 | 搜索、状态筛选、排序、分页、当前页全选、批量配置及限制 |
| A03 | 追踪具体任务 | 状态队列、账号归属、独占任务、执行观察、平台结果与历史 |
| A04 | 管理运营财务 | 订单筛选、钱包流水、对账说明、人工余额调整及审计 |
| A05 | 配置系统策略 | 独立分组设置、脱敏字段、连接与功能性测试区分 |
| A06 | 管理公开模型与题库用量 | 模型目录、可见性、价格版本、缓存命中、token 用量与测试 |

## 正式 MVP 必须解决

稳定身份映射、会话过期与凭据加密；用户资源归属及管理员权限；任务点识别、任务独占与限额调度；持久化状态、恢复、分类限次重试与二次核验；支付验签、账本原子更新、幂等、对账和失败资金处理；配置、监控、备份与基本隐私流程。

题库 fork 的正式 MVP 还需要：公开模型目录、请求级模型选择、精确缓存与 `always_llm`/`cache_first` 两种模式、token 用量回传、幂等查询、缓存失效和用户答案确认；主平台据此完成题库独立计费。模型初始条目和 token 单价由管理员面板配置；未配置前保持真实收费关闭。

高并发量、兼容课程范围和外部服务授权需要实际验证，不能用合成图表或既有少量实验代替。

## 已确认与待决定

- 已确认的视觉决定：默认石墨，青禾和靛蓝供用户切换，不再列为未决项。
- 已确认用户端为 Flutter Web + Flutter Android/iOS，管理员保持独立 React。
- 已确认主服务按用量，计量单位为平台已确认的有效任务点；题库按 token 单独收费。单价、计价精度和题库具体规则尚未确定。
- 已确认 ZPay = zpayz.cn；真实商户配置、平台授权与业务准入仍需核对。
- 已确认正常到账余额原则不退回、自有下载站地址暂缓、先 Web/原生闭环、约 2C4G / 30GB。
- 数据保留与恢复默认值由工程侧制定，见 `docs/architecture/data-retention.md`，不把目标写成实际已验证能力。
- 已确认 fork OCS-Tiku 做二次开发：模型目录、精确缓存、token 用量；fork 使用独立 PostgreSQL 数据库。

尚未确定：初始公开模型条目与上游供应商、token 单价/精度、缓存检索费、共享缓存、结算批次和题库数据跨境/保留细则；模型清单与单价入口已在管理员面板中配置。
- 已确认的数据库决定：正式服务统一使用 PostgreSQL，不维护 SQLite 后端；按真实写负载验证连接池、事务和恢复。

完整决策项、建议、责任和最晚时间见 [产品决策与外部核实清单](decision-checklist.md)。
