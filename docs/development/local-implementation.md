独立 fork 分开管理提供商、模型和公开价格，兼容已有模型内嵌连接配置。模型与密钥使用一致快照；精确缓存按实际连接、图片转述及有效预算隔离，异常上游调用与已确认部分用量进入复核。题库新增迁移 `000006_panel_pagination.sql`，升级时需先备份并显式执行题库迁移。旧格式答案缓存升级后不再命中，幂等事实保留。

### 真实测验执行与字形解码

维护环境用真实账号跑通了完整链路：安排启用题库策略后，原生执行器读取未作答试卷、逐个题目调用 fork 的 v2 作答接口、确定性映射、重新读取比对、最终提交，再由独立核验确认任务点。工程概论第1至4章测验连续确认，其中第4章首次经过“字形解码”路径。

未作答测验页面使用随机码点加内嵌字体渲染题干与选项。当前适配器将实际使用字形与原版字体完整 Unicode 目录做几何核对，还原文本和 `aria-label` 属性；历史精确签名仅兼容少量视觉别名，缺少可信字体、实际轮廓损坏或歧义未解决时停止。参考库与只读审计见[题面字形解码](secretfont-index.md)。同时修正两处判定：

- 测验卡片没有完成字段，核验改以工作页的已提交/已批阅标志为准；未作答页面里的“重做”“作业详情”等模板文字不再被当成完成。
- 执行前核验对测验返回未知时放行给工作执行器，由它重读试卷并自行确认是否已提交；其他任务仍然阻断。
- 缓存分项费率为 0 时，上游未返回该分项按 0 计价；此前这种情况会被判成计价失败并进入待复核。
- 题库调用改为「题库拥有生命周期」：fork 后台执行，调用方断开不再产生 `request_unknown`；主服务等待窗口到点返回 `202 fork_pending` 并保持 `pending`，同键重试读取已落库结果。详见[题库调用超时与结果归属](../architecture/question-timeouts.md)。

## 测验完成判定修复

本地核查发现，安排创建后 141 个章节测验在一分钟内被标记为“测验已提交或已批阅”并确认，实际从未读取到可作答表单、没有进入执行器、没有题目查询和提交记录。根因是执行前核验和页面解析把“我的答案”“正确答案”“已完成”等模板文字当成提交证据，并且把“读不到可作答表单”当作已完成。

修复后，`checkWorkSubmitted` 复用执行器的结构化页面解析，只有页面被判定为已提交才返回完成；解析失败或页面结构不明确时返回未提交，交给执行器重新读取，执行器无法识别时任务停在需要处理。提交标记收紧为已批阅、本次成绩、无需重复提交、已提交过、提交成功，或“我的答案”与“正确答案”同时出现；“重做”“作业详情”“查看正确答案”“已完成”不再作为依据。

本地已按确认原因 `pre_completed_platform_confirmed_no_charge` 回滚受影响的测验任务为待执行，暂停对应安排后用管理员账号操作恢复。恢复后 141 个测验全部真实读取页面，均因“测验题目使用字体加密，无法可信解码”转入需要处理；没有再次误判完成，没有提交，没有扣费。视频任务的确认来自课程快照中平台已通过且播放时长大于零的事实，未在本次回滚范围内。该次回滚时字形索引尚未覆盖这些字体；后续已补充字体来源识别、关闭状态核验和原版完整字体几何解码，不能把这次历史失败视为当前覆盖结论。

## 测验页面与字体解码修复（本轮）

本地核查发现新课程测验页面与早期夹具不同：`font-cxsecret` 类仍在元素上，但字体不在内联样式，而在外部样式表（部分通过 `@import` 间接引用）；页面文本为明文时也会出现该类名。旧逻辑因此把明文页面当成加密页并整体转人工，换课程全部失败。

解码器现在收集外部样式表中的全部 `@font-face` 候选字体并逐个试解码，只采用能完整还原整页文本的字体；新增 CFF/CFF2 字形解析、WOFF1 解包、空白字形按空格处理，并跳过脚本与样式节点中的模板文本。没有可用字体且文本不含私用区码点时按明文解析。

完成判定同步收紧：只有“我的答案与正确答案同时有值”“已批阅并带分数”或明确提交状态文字才算已提交；单独的“本次成绩”标签不再触发自动确认。页面有题目但没有答题控件和提交字段时按不可作答转人工。

修复后重试本安排的 141 个测验，全部返回只读查看页（form 存在、题目存在、无答题控件和提交字段），因此保持需要处理，没有再次误判完成、没有提交、没有调用题库、没有扣费。视频 248 个仍按课程快照的平台通过事实保持已确认。若平台重新开放这些测验，可用任务重新调度再次尝试。

## 测验关闭状态（本轮）

平台卡片 JSON 只给 `work` 附件 `jobid` 与全为 0 的 `begins`/`ends`，`property` 也没有截止字段，因此关闭状态不能从课程同步直接得出。实测构件：已关闭测验页面有题目，但没有答题控件和提交字段。

新增判定与存储：

- 执行前核验将“有题目、无答题控件、无提交字段”识别为 `platform_closed`，不再当作能力缺失；
- 任务记 `last_error_code=quiz_closed`，保持 `needs_attention`，不重试、不扣费；
- 任务点可用性写入稳定表 `learning_task_point_availability`（迁移31），按课程、章节外部编号、任务点编号和周期唯一；附件 `availability` 同时回写兼容；
- 课程重新同步会重建附件行并升快照版本，但可用性不再随版本丢失，课程计数按稳定表关联当前快照任务点；
- 新安排绑定会跳过已关闭任务点，已有绑定保留为历史事实；
- 安排汇总 `progress.closed` 单独计数，待处理不再包含这些任务，完成率分母排除已关闭与已取消任务；
- 课程接口返回 `closed_task_point_count`，课程列表、详情和安排编辑课程行显示已关闭任务点数量，待完成数也排除已关闭；任务列表和详情显示“已关闭”而不是笼统的失败；列表行与详情底部均提供“重新调度”，已关闭任务显示为“重新检查可用性”，重新读取平台页面后再决定是否继续。

本地将安排内 141 个测验全部重新执行，均识别为已关闭并回写 `availability=closed`；题库查询为 0，没有提交与扣费。视频 248 个仍保持平台确认。

首轮回写只改了当时快照版本的附件行，随后一次课程同步升到新版本并重建附件，关闭状态在课程接口里归零。迁移31把状态改存到稳定任务点身份并回填了 141 条 `closed`，课程接口现在重新返回正确的已关闭数量。

## 课程级关闭状态（本轮）

学习通课程列表用 `<a class="not-open-tip">课程已结束</a>` 标记整门课程已结束。同步时解析该标记并写入 `learning_courses.platform_state`（迁移32，`active/closed/unknown`），不再靠任务点逐个判断。

效果：

- 已结束课程的在待执行任务统一转为 `needs_attention` + `course_closed`，不再派发；课程重新开放时恢复为待执行。
- 新安排绑定与任务领取都排除已结束课程；保存安排时直接拒绝包含已结束课程的选择。
- 课程列表、详情和安排编辑课程行显示“已结束”，待完成与进度分母不再包含这些课程；已结束课程在排序中靠后。
- 已关闭任务在任务筛选里单独成组，不再混在“需要处理”里；测验关闭仍记 `quiz_closed`，课程结束记 `course_closed`，两者都不进入完成率分母。

本地真实同步后 35 门课中 13 门为 `closed`，464 个待执行任务转为 `course_closed`；此前 141 个测验关闭状态仍保留。没有提交、没有题库调用、没有扣费。

## 原版字体几何解码（本轮）
