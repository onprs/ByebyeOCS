本文面向开发维护环境，记录当前源码与真实本地验证；公开安装使用 [部署指南](../../deploy/README.md)。本地身份、课程、平台回读、模型计量和支付供应商测试夹具均为合成数据，夹具只编译进测试二进制。

源码通过本地Git管理，接续远程仓库的原有历史；尚未创建线上Release或部署外部主机。实际环境配置、研究目录、凭据、运行数据、本地验证截图/报告和构建产物由忽略规则排除。

## 验证记录

基础工具为 Go 1.27.3、PostgreSQL 16.15、Flutter 3.47.7、JDK21 和 Android36。它们是本次维护环境，公开系统要求见 README 和部署文档。

已通过的组合检查：

- 两个独立 HTTP 监听上的用户/管理员真实认证、主体绑定、钱包、课程同步、越权隔离、版本冲突、CSRF和安排创建。
- 同一有效任务点在正常收费、未定价、运营停收费与明确零价下的报价/预占/平台确认/结算；运行时发布新价仍保留原价，重复确认不重扣。
- 题库真正调用账本做最坏预算预占、按服务端 token 结算；相同幂等键只调用一次；运营关闭收费后查询仍可用、钱包不变。
- 删除申请立即撤销，管理员延后/驳回、同主体重新验证、再次申请完成后禁止复活的完整 HTTP 流程。
- 独立题库模块的 vet、竞态与隔离 PostgreSQL 集成测试。

主服务已通过最新全量 `go test -race -count=1 -tags=integration ./...`；隔离库清理采用正常删除优先和有界重试。独立题库vet及竞态/数据库测试通过。真实pg_dump、age1.3.2、临时initdb/pg_restore检查通过，本地归档未写成异机恢复点，源用户/钱包保持750分不变；连接用libpq官方解析器写私有service/pgpass文件，密码不进入argv。

此前隐私阶段补齐生产验证器内部登录/只读授权接线及安全错误映射，并通过无网络装配回归。该阶段管理员30测试、Flutter32测试与真实双端隐私延后/驳回/完成复演通过。管理员测试依赖升级到Vitest4.1.11后重跑通过，npm audit为0项；界面只收口面向用户的状态与操作文案，OpenAPI和业务语义保持已验收状态。

上一轮含17个迁移的 amd64 发布目录经过临时路径安装：配置/独立密钥生成、未迁移拒绝、17个迁移/重复迁移与实际记录数核对、doctor、TOTP管理员创建和HTTP登录、双端静态资源/权限、SIGTERM退出、保留配置/密钥/数据卸载均通过。修复了私有umask导致版本目录无法被专用服务用户遍历的问题；24项部署/备份脚本隔离检查通过，未安装真实systemd单元或发出SSH。arm64两个二进制完成交叉构建，未在arm64设备运行。

发布目录附文件SHA-256、当前OpenAPI/文档及已有依赖许可证/NOTICE；Go标准库、实际Go模块与管理员生产依赖按构建收集，Flutter自身NOTICES随静态应用保留。40份主文档的相对链接在源码和发布目录均无缺失目标。外部前提不以合成数据补齐。

## 原生HTTP执行与低内存验证

依据[ADR0009](../decisions/0009-native-http-execution.md)，正式入口已改为原生HTTP视频任务执行器，移除浏览器代码、路径配置和浏览器部署drop-in。普通协议保持平台卡片中的任务归属、时长、间隔、签名及来源上下文；按实际经过时间执行，不覆盖时间、跳过交互或下载媒体。缺少可核验保存位置/上下文、验证码、抓拍、视频内交互和不支持的任务进入人工处理。

请求执行记录不产生真实播放证据。执行前预检、执行后独立平台确认与账本契约保留，全局并发按配置生效。共享限速器按实际放行时间推进并允许取消排队，避免延迟时间槽形成突发。主服务和题库的vet、竞态及实际PostgreSQL集成检查通过。题库补充显式数据库池上限与按配置目录解析私有文件路径。

本地在约1GB、无Swap、200%CPU配额的同一cgroup内运行PostgreSQL16.15、正式主服务、正式题库和原生协议夹具；完成60秒普通请求序列、两次密码校验、40次管理API/40次静态入口读取及一次双库pg_dump/age加密备份。采用主服务 `e5e6d29` 与独立题库 `3b80c40` 的复验峰值约333.1 MiB，内核限额核对通过，内存上限/OOM事件均为0。题库待机，自动测验的模型与提交负载尚未纳入。Go软目标192/96MiB、数据库池4/2、PG shared_buffers=64MB。未计宿主系统、HTTPS代理、长期数据和真实外部负载，不能据此承诺真实用户数。低内存配置与范围见[容量记录](../architecture/capacity.md)。

## 全自动测验与独立题库

依据[决策0010](../decisions/0010-automatic-questions.md)，安排启用题库策略后自动取题、查询、确定性映射、最终提交与独立复核，没有人工确认或手动提交入口。旧确认字段兼容解析后恒为 false。单选、多选、判断、填空与简答均有受控协议夹具；混排 HTML 保持原顺序，真实验证控件与普通题干文字分开识别。

试卷包含当前作答机会、选项值与图片实际内容指纹；提交前重新读取并比对。`beforePost` 在 HTTP 请求就绪时核对暂停、闭户和 fencing，并持久化提交标记。查询恢复复用原键，最终提交结果不明只核验；新安排版本不能绕过任务级提交独占。图片整卷原始上限16MiB，模型响应上限8MiB，后台与手动查询共享并发名额。

主服务新增000016自动做题与000017题库恢复迁移，全部17个连续迁移通过隔离PostgreSQL测试。真实调度/查询/账本端到端验证覆盖五题型直接提交、响应丢失后确认、无效答案不提交、usage不完整继续作答但不扣费。恢复、闭户/取消/过期租约、最终POST前fencing变化与跨版本防重交测试通过。主服务完整vet及`-race -count=1 -tags=integration`通过；协议解析后续收口再次通过原生适配包竞态测试。

独立仓库为 <https://github.com/onprs/ByebyeOCS-Tiku>，保留上游 `aedb64fb0b55b633362558c627887d0f1f4de565` 之前的完整历史。主仓库 `services/tiku` 为固定提交子模块。v1和v2共用提取后的上游模型、图片与答案核心；正式平台命令不导入SQLite，旧上游本地服务作为单独兼容路径保留。fork的回环TLS测试覆盖真实token、缺字段/矛盾usage、错误脱敏、响应体上限、连续always_llm调用和后续精确缓存命中。来源与同步说明在该仓库 `UPSTREAM.md`。

两仓库CI均通过。Flutter当前33项测试、analyze、Web release和Android Debug APK构建通过；已移除固定确认提示、确认复选框、弹窗、旧手动提交接口及其模型。旧题库人工提交API不再注册，OpenAPI同步删除。

## 维护命令

```bash
make check-go
BYEBYEOCS_TEST_DATABASE_DSN_FILE=/path/to/private/test.dsn make test-integration
make check-admin
make check-flutter
```

隔离测试角色需要 CREATEDB；测试工具创建并清理随机临时数据库，不能使用真实业务实例。真实备份检查额外要求 PostgreSQL16客户端/服务端工具、age、age-keygen，并显式设置 `BYEBYEOCS_RUN_BACKUP_TEST=1`；只生成本地加密归档和临时 initdb，不发 SSH。

本地浏览器服务由 `TestBrowserFixtureServer` 显式启用，静态应用直接调用组合 Go/PostgreSQL 服务。合成验证器与课程源在 `_test.go`，正式二进制不包含默认账号或此入口。原型端口5186及其他项目保持独立。
