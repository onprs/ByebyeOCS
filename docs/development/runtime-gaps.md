# 异常恢复与运行期边界防护机制

> **适用范围**：开发维护环境，汇总系统针对进程崩溃、网络半途中断、上游会话轮换、账务对账补偿及存储/备份异常所实施的状态收敛与防损机制。

## 1. 任务执行与自动交卷的崩溃安全恢复

1. **已交卷任务防重放直达核验**：章节测验在向学习通发出最终交卷请求前，先在主库 `learning_work_runs` 落盘 `submitting` 状态。若交卷途中连接中断、进程重启或用户在异常后点击“重新调度”，调度恢复器检测到该标记后**跳过题库查询与表单提交，直接进入 `verifying` 独立平台只读核验阶段**，从根本上杜绝重复交卷耗尽重做机会。
2. **两轮瞬态冷却与三代显式重查（主库迁移 34）**：
   - 区分可恢复网络错误（超时、连接重置、`502/503/429` 并遵守 `Retry-After`）与确定性业务阻断（验证码、`403`、登录失效、字形歧义）；常规重试耗尽后对瞬态故障最多自动执行 `2` 轮冷却恢复，独立核验阶段最多容忍 `12` 次有界轮询。
   - 当历史查询因空答案或平台重排导致无法映射时，仅在用户显式点击重试时允许开启新查询代次（最多 `3` 代），防止后台无人值守死循环消耗模型额度。
3. **当前租约观察回传与终态版本对齐**：执行期间的进度观察严格校验当前有效租约与 `fencing_token`，任务结束写入终态事件时直接读取同一数据库事务提交后的真实状态与递增版本号，消除前端状态闪烁。

## 2. 题库在途回收与前置失败恢复

- **脱离连接生命周期 + 30 秒回收器**：题库服务在独立后台上下文完成上游调用与缓存落库；主服务等待超时返回 `202 fork_pending` 后，后台每 `30s` 通过 `GET /internal/v1/requests/{idempotency-key}` 自动回收已完成结果并走冻结快照结算，全程不产生二次上游调用。
- **前置白名单重驱动**：仅对明确未触达上游模型的本地前置拒绝（如余额不足、模型临时下架），允许在充值或恢复配置后为同一查询开启新代次预占继续执行；而包含 `request_unknown` 的记录锁定为待人工核实，仅允许管理员核对账单后通过受控释放接口归档旧幂等键。

## 3. 同步安全、账号管控与财务补偿边界

1. **单次同步隔离 Cookie 容器与管控联动**：课程同步全流程共享按平台实例与会话指纹隔离的内存临时 Cookie 容器，既兼容上游目录跳转时的动态 Cookie 接力（消除目录 `403`），又不污染持久加密会话。排队领取、续租心跳与快照落库前均实时检查账号限制、暂停指令与用户闭户互斥锁，受限期间不空耗重试次数。
2. **合法空目录与异常结构分离**：确认属于当前用户的空课程列表或“暂无章节内容”记录为正常成功空态；HTML 结构无法识别或身份字段残缺时立即报错停止，绝不用空快照冲掉既有课程任务。
3. **财务对账覆盖与未发出退款释放**：管理端主动查单对账同时覆盖 `pending`、已付款未入账及异常关闭订单，确保延迟到达的真实渠道收款总有恢复入账路��；尚未实际发往支付渠道的 `requested` 退款在确认失败后可安全回退并释放冻结资金。
4. **答案报告幂等结单**：管理员在任务监控底部复核用户答案问题报告时，支持对非缓存查询直接记录处理结论结单，或对缓存查询联动失效精确缓存，操作绑定管理员身份与幂等键，已结清报告立即移出待处理列表。
