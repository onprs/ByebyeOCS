# 正常运行缺口复查

本文面向开发维护环境，记录在已配置条件下阻碍正常流程的问题。未提供真实账号、商户、模型密钥、价格和设备验收属于外部条件，不作为代码缺陷。本轮只使用隔离PostgreSQL、受控HTTP/TLS和前端测试。

## 身份恢复与任务控制

- 平台会话失效后，同一主体重新登录原本仍保留identity_invalid，课程同步继续409。现在只有晚于阻断的新鲜同主体凭据验证可清除此标记；旧验证结果、管理员限制、平台交互、权限拒绝及冷却独立保留。
- 对运行中的任务重复点继续原本会取消当前尝试；暂停后立即继续也会被迟到的停止确认覆盖为paused/run。现在继续不制造新停止请求，已开始的停止握手结束后按最新运行意图重新领取，保留原报价、预占及查询事实。
- 已发送最终提交的测验，恢复或重新调度直接回到独立核验，不先领取一次执行再拒绝提交。控制结果版本与数据库版本一致。

## 课程读取与在途停止

- 课程入口接受合法HTML实体、任意查询参数顺序和附加参数；封面与名称重复链接去重后不再错位。身份字段不完整时明确停止，避免保存截断列表。
- 一次课程同步从课程列表到各课程发现共用按平台实例和原始会话指纹隔离的Cookie容器。响应Cookie轮换在本次操作内连续，结束即释放，不改写持久化会话。TLS与实际调度/数据库组合回归证明旧独立作用域在目录入口收到403，新作用域成功。
- 排队同步、在途续租、外部核验领取及发送前检查用户/账号限制和冷却；限制期间不消耗排队尝试，不继续发出平台读取。课程快照写入与用户停用/闭户互斥。
- 适配器明确返回的空课程列表记录为成功空结果，不再显示no_courses故障；未知HTML结构仍明确停止。

## 双端与业务入口

管理员近期验证错误码与前端对话框约定一致；数据库暂时不可用时保留仍可能有效的登录Cookie。支付对账覆盖待核对、已付款未到账和指定关闭订单，避免正确渠道事实永远无法进入恢复范围。

服务计价支持UI已经提供的ceil，并兼容floor和half_up；整数商余取整避免溢出。后台移除未用于实际计费的全局题库费率编辑，钱包明确按所选模型计费。未发出的requested退款可记录失败并释放资金；已退款订单优先显示退款状态，详情打开会读取最新付款地址。

用户从设置进入独立题库查询页，支持题库面板发布的公开模型、两种查询模式、文字题输入、展示结果和报告答案问题。自动任务仍全自动。隐私页明确提示近期验证并提供重新登录入口，模型列表按游标读取。

题库前置失败恢复只接受明确未开始模型调用的白名单错误。余额不足后充值、恢复模型配置后可以沿用原查询编号恢复；原预占已释放时开新代次预占，保留原模型价格和收费决定，不复用关闭的hold。即使重试前切换价格或收费开关，原免费与已定价决定保持。重驱动开始后、预占前进程退出可按冻结事实继续；未知费用、超时、有调用事实和通用上游故障不通过新请求重发。较小模型输出上限会约束实际调用，请求预算仍是不可突破的上限，服务全局硬上限继续校验。

管理员在题库页读取用户答案报告，可独立记录处理结果或使错误缓存失效。非缓存报告也能结清；报告复核绑定管理员、业务键、报告、状态与理由，冲突和并发不会覆盖终态。响应仅包含最小查询、模型和缓存引用；报告解决后不再滞留于待处理列表。

## 公开配置与维护说明

生成配置给出默认备份恢复点路径；回环代理范围、安装后续步骤、题库显式迁移与支付回调示例和真实监听保持一致。公开回调路径仍可由用户自管HTTPS代理重写，不通过静态配置猜测公网拓扑。ZPay的[官方文档](https://zpayz.cn/doc.html)明确notify_url与return_url均不支持查询参数，配置检查与支付客户端保持一致，避免检查通过后启动才失败。

正式题库命令启动前只读核对迁移版本、名称与校验值，空库或不匹配库明确退出；迁移仍单独执行。`/healthz`表示存活，`/readyz`检查数据库和迁移就绪。静态资源及已鉴权的就绪导出使用5分钟输出期限，普通API保留原短期限；实际HTTP延迟写入回归覆盖两类期限独立。

共享缓存通过主服务`questions.allow_shared_cache`显式开启，默认false；公开能力反映运行开关，仍要求模型缓存策略和独立fork允许共享。

## 证据边界

回归覆盖真实本地API登录、调度、行锁、资金事务、课程Cookie轮换和双端异步操作；受控成功不代表真实学校、模型正确率、生产支付或设备分发成功。旧资源测量不扩展为本轮代码的容量结论。
