# 任务覆盖范围与完成判定规范

> **适用范围**：开发维护环境，详述 `server/internal/learning` 与 `server/internal/adapters/chaoxing` 对各类学习通活动的支持范围、完成确认标准、三级平台关闭模型及异常停机边界。

## 1. 任务类型支持矩阵

仅带有平台明确任务点标识（`jobid` / 任务点状态位）的附件会建档为待执行任务；普通无任务点编号的参考资料（课件 PPT、补充附件等）在目录详情正常展示，不计入未完成分母，也不触发调度。

| 平台活动类别 | 调度支持状态 | 原生 HTTP 执行行为 | 独立平台完成确认（`confirmed`）唯一依据 |
| --- | --- | --- | --- |
| 普通视频（`video`） | 自动执行 | 读取新鲜卡片（含 `card_index`）、媒体长度与历史保存位，按真实流逝时间与平台间隔签名上报观察进度 | 独立重读章节卡片，目标任务点明确返回已完成标志 |
| 明确音频（`audio`） | 自动执行 | 与视频同源签名推进，仅针对卡片明确标识为音频的任务点 | 独立重读章节卡片，目标任务点明确返回已完成标志 |
| 文档与阅读（`document`） | 自动执行 | 不因初始卡片缺失完成布尔位而阻断；请求 `/ananas/job/document` 考核接口，未即时确认时至多追加一次幂等只读复查 | 考核接口明确返回平台已完成语义（如“考核点已经完成”）或重读卡片显示已完成 |
| 章节测验（`quiz`） | 全自动执行（五类标准题型） | 支持**单选、多选、判断、填空、简答**；动态混淆题面经几何轮廓目录还原，请求独立题库，重读核对试卷后先持久化提交意图再发送最终交卷 | 独立读取测验工作页 HTML，核实存在**带具体取值的已提交答案、已批阅具体得分，或明确“已提交/无需重复提交”状态** |
| 其他复杂活动（`other`） | 保持未支持 | 直播、讨论、分组任务、连线/排序/口语等非标交互题不伪造请求，直接转入人工处理并说明原因 | 用户在原平台完成后，可通过同步或重新核验同步平台完成结果 |

## 2. 测验完成判定的防误判红线

学习通测验卡片 JSON 本身不包含可靠的完成字段，且部分未作答或只读模板页面含有容易混淆的静态文案。解析器严格遵守以下防误判规则：

1. **拒绝空壳标签误判**：页面仅出现空白的“本次成绩”标题、无具体取值的“我的答案 / 正确答案”占位标签，或未作答页常见的“重做”“作业详情”“查看正确答案”按钮文字，**一律不构成已完成事实**。
2. **只读无控件试卷区分**：若页面包含题目正文但既无任何已提交答案/得分证据，又不存在可填写的表单控件与提交按钮：
   - 若页面同时带有明确的未开放或截止提示，归类为平台已关闭（`quiz_closed`）；
   - 若无关闭提示但无法作答，保持“需要人工处理（`needs_attention`）”，绝不静默标为已完成、不发起盲目提交、更不触发任务点扣费。

## 3. 课程、章节与任务点三级平台关闭模型

平台按教学日历未开放或已截止的内容属于客观不可执行状态，系统在三个粒度持久识别并统一治理：

| 关闭层级 | 平台页面特征与存储位置 | 系统联动行为 |
| --- | --- | --- |
| 课程级关闭（迁移 32） | 课程列表容器含 `not-open-tip` 已结束标识，写入 `learning_courses.platform_state` | 课程页标记“已结束”且不计入待完成；禁止选入新安排；存量待执行任务记 `last_error_code = course_closed` 并停止派发 |
| 章节级关闭（迁移 33） | 目录节点移除进入链接且带 `icon-bukaifang` 或明确“已关闭”提示，写入章节 `availability` | 保留目录节点层级与历史已同步附件/核验时间，跳过隐藏卡片请求；跳过安排绑定与派发，对在途任务发起安全停止握手 |
| 任务点/测验级关闭（迁移 30, 31） | 执行前或复核时检测到测验未到开放时间，或明确提示“已截止，不能作答”（即使页面仍残留表单 DOM 也在查题前立即阻断），写入稳定表 `learning_task_point_availability`（`platform_closed`） | 任务记 `quiz_closed`，保留历史已有查询或交卷事实，不随课程快照版本重建而丢失关闭状态 |

**统一统计与重检语义**：所有处于平台关闭状态的任务自动退出“待处理”列表、退出安排完成率分母，且在管理端运行总览单独计入 `closed`（不混入 `actionable_attention` 异常告警）。任务行与详情面板对关闭任务显示**“重新检查可用性”**，触发后先刷新目录与工作页，确认平台重新开放后自动恢复待执行状态（已持久化最终交卷的任务仍仅执行只读核验）。

## 4. 验证拦截、抓拍配置与真实播放证据边界

- **前端抓拍配置与真实身份核验区分**：音视频卡片元数据中的定时抓拍时间点列表仅用于驱动官方网页播放器弹窗，平台服务端进度接口与完成核验均不消费抓拍回执，故原生执行器不因该静态字段阻断任务；一旦上游实际响应要求图片验证码、人脸核验、`403` 权限拒绝或登录失效，立即停止对应任务（会话级失效才冻结整账号，单任务验证仅停该任务）。
- **无真实播放记录声明**：原生 HTTP 执行全流程不解码渲染音视频流，任务详情始终如实展示无真实媒体播放证据。
