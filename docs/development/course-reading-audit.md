# 课程目录树解析与读取一致性设计

> **适用范围**：开发维护环境，说明 `chaoxing-read-v2` 课程目录解析结构、多级章节父子关系保留、同媒体多任务点拆分以及数据库快照读写一致性保障（对应主库迁移 27–28 及 `server/internal/learning`）。

## 1. `chaoxing-read-v2` 多级章节树建模

学习通课程目录常采用“单元 / 章分组（无直接卡片链接） → 节 → 子小节（最深可达五层以上）”的嵌套 DOM 结构，且章节标题自带多样化的原始编号（如 `1.1`、`项目二`、`专题三`）。解析与存储层遵守以下规则：

1. **完整保留章分组与前序顺序**：适配器按页面 DOM 真实文档流前序遍历提取全部章分组节点与实际可进入小节节点，记录 `parent_external_id`、原始章节编号与排列序号，严禁按外部数字 ID 或标题字典序重排目录。
2. **分组节点与可执行小节边界**：章分组节点仅承担树形目录折叠容器职责（无卡片内容、不发起 `studentstudyAjax` 请求、不作为任务执行目标）；用户在安排中选择课程后，服务端自动展开绑定其下所有开放的可执行小节。
3. **跨同步周期稳定小节 UUID**：同一门课程重新同步生成新 `snapshot_version` 时，系统预先查询该课已有 `learning_course_chapters` 映射并复用相同 `external_id` 对应的内部章节 `UUID`，确保已绑定的安排、任务外键与章节级可用性状态跨快照平滑延续。

## 2. 同媒体多任务点精确拆分与卡片定位

部分课程在同一章节甚至同一媒体对象（相同 `objectid`）上配置了多个不同 `jobid` 的任务点，或跨多张标签卡片分布附件：

- **复合附件唯一键**：`learning_course_attachments` 以章节、卡片页码 `card_index`、任务点标识 `job_id` 与媒体对象标识组合区分记录，避免同一视频关联多个任务点时后一记录覆盖前一记录。
- **实时个人进度聚合**：课程列表页的完成比例、章节树节点状态与附件行勾选状态统一关联查询同一稳定任务点的最新平台核验事实。当后台某个任务刚刚通过平台核验或被判定为 `platform_closed` 时，前端收到 SSE 事件重拉课程接口即可立即看到最新进度，无需重新发起整课目录同步。

## 3. 数据库写入完整性与可重复读快照查询

### 3.1 写入前树校验与有界批量提交

单门大课程可能包含上百个章节与数百个附件。快照落库前先在内存完成父引用闭合校验（无悬空父节点、无环路），随后在单个课程快照更新事务中按有界批量语句写入章节与附件；任一批次失败整门课程原子回滚，旧版完整快照毫发无损。

### 3.2 详情查询只读可重复读事务（`REPEATABLE READ`）

由于重新同步会原地更新课程概要的 `snapshot_version` 并复用稳定章节行，若课程详情接口分三次独立自动提交查询分别读取课程头、章节列表与附件列表，并发同步恰好提交瞬间可能读到“新版课程头 + 旧版附件”的撕裂视图。

因此，`GET /api/v1/courses/{id}` 强制在单个 **只读 `REPEATABLE READ` 数据库事务快照** 内一次性读取课程概要、对应 `snapshot_version` 的章节树、附件列表及稳定任务点核验状态，从事务隔离级别根除读写并发撕裂。
