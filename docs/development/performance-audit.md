# 性能、缺陷与异常处理排查

本文面向开发维护环境，记录全项目源码检查与受控回归。公开功能和部署步骤见README与部署指南。本轮不连接真实学习通、付费模型、支付渠道或生产主机；隔离PostgreSQL和HTTP/TLS夹具的结果不代表真实学校兼容或生产容量。

## 学习调度与数据库读取

- 领取候选在截取100条之前排除账号并发已满的记录。原实现可能让一个账号的大量待执行任务占满候选窗口，其他账号有空闲名额也无法领取。130条同账号任务加另一账号的回归覆盖此情形。
- 课程同步在整个目录读取期间维护租约，续租失败取消外部读取。原实现只在课程之间续租，单个较长课程会在保存前丢失所有权。150ms租约与400ms受控读取的回归覆盖跨租期同步。
- 心跳与恢复按任务、尝试的同一顺序取得锁；仅续当前租约及fencing匹配的尝试。锁等待回归验证结果写回与心跳能相继完成。
- 学习服务退出等待执行协程实际清理，并有总等待上限；全局停止保留未完成租约供恢复先核验，不把取消会话读取当作账号失效。
- 平台会话失效、数据库暂不可用、超时和取消分别分类。内部暂态故障不永久阻断用户身份。
- 学习及维护接口限制数据库和行锁等待。超时返回可重试错误，事务及保存点有界回滚，不保留半完成控制。
- 课程同步完成状态与Outbox在同一事务提交；事件写入失败时完成状态回滚。
- 列表按页批量读取安排关联和选定章节，保持排序、游标、用户归属及真实模型策略。100条任务及20个安排关联实测共2次SQL；普通10条安排页实测1次SQL，选定章节另用一次批量查询。
- 长中文课程、章节、任务及学校显示字段保持有效UTF-8边界，避免截断后无法写入PostgreSQL。身份键与主体校验规则保持独立。

## 事件、保留清理与服务退出

- Outbox投递和课程事件桥接改为整批写入，数据库往返不再按事件逐条增长；事务领取、流内序号、双端最小载荷及发布确认保持一致。多个流按稳定顺序加锁，避免批次次序形成反向锁等待。
- SSE在投递批次前复核当前会话和权限，限制读库与校验等待。空闲事件查询逐级退避至3秒，有事件后回到1秒；权限撤销仍按秒复核。空闲后首个新事件最多等待3秒，此范围有别于持续事件流。
- 停止服务会主动结束SSE流，避免长连接把正常退出拖到HTTP停止超时。实际HTTP监听与事件服务组合回归覆盖活动流停止。
- 流记录删除与最早可用游标同事务推进，中断后仍可重试，不会把已删除事件误当可续传历史。
- 保留作业在启动时先执行一次有界清理，再进入周期，避免短周期重启导致临时数据永不清理。
- 导出下载在读取密文前限制并发，避免密文和明文按任意并发倍增；后台失败只记录安全分类码，并对重复故障节流。
- 000019为事件外键查找、钱包与退款分页、账本范围筛选增加索引。5,000条投递记录的缺失事件查找实测从26个缓冲块降至2个；这是本机查询计划证据，不是整机吞吐承诺。

## 钱包、支付与退款异常

- 新退款在发起渠道请求前持久化提交标记。旧版本reserved可能已经发过请求，不能据此推断未发送；未知结果不自动重发。
- 管理员可在核实渠道事实后记录已退款或未退款结果，复用既有结算或释放分录；要求退款权限、近期验证、幂等请求和理由，并保留审计。复核键绑定具体退款、结果与理由，同键不同负载返回冲突。该入口不调用渠道，不依赖新退款开关。
- 渠道调用期限在提交开始时固定；数据库等待与进程停顿不会延长可发送窗口。渠道返回后调用方取消，仍用独立有界上下文持久化退款事实和账本结果。
- 管理员钱包页按创建时间和编号索引读取。5,000个钱包的数据集中，LIMIT 21的查询由排序前执行5,000次LATERAL读取降至21次，缓冲块由10,082降至45；范围账本汇总先限定类型和时间，再统计金额。

## 题库与模型调用

- 多图题按实际支持的图片数核对完整用量，避免合法caption调用被固定数量上限误判为缺失。
- 请求取消后，以独立有界上下文保存已经发生的查询/用量事实并完成预占处理；保留明确的取消与未知结果分类。
- 缓存写入失败不会把已经完成的模型回答变成再次付费的机会；陈旧pending幂等请求返回明确未知状态，不高频轮询或重新调用模型。
- 缓存失效回传实际结果；不可用默认模型与永久上游请求错误如实分类，不用无限重试掩盖配置或输入问题。
- 预占提交回执中断时，失败处理先等原事务落定并核对持久化查询；原预占已存在则复用事务内释放及结果链，保留冻结价格和关联。真实账本回归证明可用余额恢复、预占归零，同键不再调用模型。
- 主库清理显式标记内容过期，并保留未处理的账务异常；fork缓存到期后删除原文，查询答案默认7天、token调用明细30天。幂等响应到期保留请求键和摘要，旧键返回结果未知，不重新调用模型。正式维护作业启动先执行一次，之后每日运行，每批500行、每次30秒上限。
- 图片同时受数量、单图、合计原始数据16MiB和HTTP请求体上限约束；正式fork不落盘原始题图。具体保留规则见[数据保留](../architecture/data-retention.md)。

## 用户端与管理员端

- 安排、课程搜索、钱包、隐私与身份引导使用账号和请求代次，迟到响应不能覆盖新账号、新安排或新搜索。
- 原生令牌读取、清除和新登录不互相覆盖；页面翻页合并同一游标的在途请求，刷新后丢弃旧页。
- 充值幂等键绑定金额和渠道；相同输入重试复用，修改输入生成新键。
- 管理员详情切换实体时清空旧详情，避免对上一任务操作或把旧钱包余额显示在新用户下。引导请求去重，退出后旧引导不能恢复登录。
- 钱包必需数据与独立分区分阶段并行读取，6个串行请求缩为2个依赖阶段；二进制导出不再生成无用的整份UTF-8字符串。
- 用户端安排任务超过50条可继续翻页，切换安排或账号后不接收旧页；刷新重新读取第一页。钱包长列表使用懒构建，120条流水回归验证末行在滚动前不创建。外观与通知按最新ETag串行保存，原生SSE每连接只计一次失败。

## 本轮验证

- 主服务完整vet与竞态/隔离PostgreSQL集成测试、独立题库完整vet与竞态/隔离PostgreSQL测试通过。
- 管理员37项测试、类型检查与生产构建通过；Flutter analyze、56项测试、同源Web release及Android Debug构建通过。
- 部署脚本57项隔离检查、公开配置校验、真实主库pg_dump/age/临时initdb恢复通过；没有发送真实SSH请求。
- OpenAPI为78条路径、95项操作、150个schema；42份主文档相对链接无缺失目标。
- 主库20个连续迁移、题库2个连续迁移；仅增加000019/000020及fork000002，历史迁移不变。

## 部署与恢复

- 安装、升级、回滚和卸载共用前缀锁；强制重装先构建和校验新目录，失败保留旧版本，清理中断临时项。
- 卸载拒绝系统级目录，清除自定义配置路径需要安装记录；升级和回滚要求可读取原安装状态。
- 本地和异机备份只在完整写入、校验后生成正式归档；失败状态不能更新可恢复点。题库DSN与配置双向核对，恢复manifest与实际内容一致后才恢复。
- 发布目录在临时位置完整生成并校验，公开清单可读取，失败重建保留原产物。备份明文工作目录、信号清理和真实恢复边界见部署说明。

## 验证边界

核心证据来自真实隔离PostgreSQL、受控HTTP/TLS、延迟/取消/行锁/写入失败夹具以及前端异步竞态测试。性能数字限于指定数据量、查询次数和本机缓冲块，不推广为真实用户数或整机容量。

真实上游时延、学校差异、模型正确率、生产数据库增长、异机网络、目标硬件及移动端实机仍需对应现场配置和测量。保留已确认的全自动做题、原生HTTP执行、独立平台确认及默认关闭真实收费。
