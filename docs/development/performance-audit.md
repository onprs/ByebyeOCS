# 性能治理与高并发优化设计

> **适用范围**：开发维护环境，汇总主服务、独立题库服务与三端客户端在数据库索引、上游请求收敛、内存控制及前端渲染层面的核心性能优化措施。

## 1. 课程同步吞吐与上游请求收敛

1. **结构指纹减少一半冷请求（主库迁移 28）**：利用课程目录结构提示复用已确认的单页章节分布，叠加跨用户 `24 小时` 共享卡片页码缓存（内存 `4,096` 条 LRU + PostgreSQL 持久化）与同键并发 `singleflight` 合并，大幅削减对上游 `studentstudyAjax` 的重复探测。
2. **动态发现槽位与自适应提速**：单课并发章节发现槽位完全跟随 `runtimeconfig.ChapterConcurrency`（最高支持 `64` 并发，消除早期硬编码截断）；请求节流器在连续 `50` 次上游成功后按 `10%` 步进平滑缩短请求间隔，直至触达配置的 `RequestIntervalFloor`（最低支持 `10ms`），遇瞬态限流即时退避。
3. **长同步锁解耦与快照直读汇总**：大课程组装与分批写入章节快照期间释放同步队列行锁，保证心跳协程顺畅续租；课程列表接口直接读取课程行上的预聚合任务点计数，避免每次打开列表扫描全量附件表。

## 2. 数据库热点索引与定期清理部分索引

- **核心业务复合索引（主库迁移 19, 27）**：覆盖待领取任务公平排队扫描、有效租约到期检查、当前安排版本绑定汇总、稳定章节 UUID 映射、用户账本流水时间倒序及未发布 Outbox 顺序拉取（`FOR UPDATE SKIP LOCKED`），并将多条 Outbox 桥接合并为单次批量 `INSERT` 与数组 `ANY($1::uuid[])` 批量确认，使 SQL 往返次数不随单批事件数线性膨胀。
- **TTL 清理部分索引（主库迁移 20、题库迁移 02–03）**：针对需定期脱敏清空大文本载荷而永久保留幂等摘要的 `question_queries`、`tiku.requests` 与 `tiku.queries`，专门建立仅包含“尚未清理正文记录”的**部分索引（Partial Index）**。即使历史累积数万条已清理的永久幂等键，每日清理任务也只扫描待清理的少量近期数据块，避免全表复扫。

## 3. 前端渲染、并发请求与资源加载优化

- **分阶段并行请求与懒构建列表**：客户端钱包页将原本串行的多个接口收敛为两阶段并行拉取；长账务流水与任务列表统一采用 Sliver 懒加载或每页 `10` 条快照游标分页，避免一次性构建上百个复杂组件节点。
- **高频 SSE 防抖与代次去重**：`RealtimeService` 对密集到达的任务进度与课程同步事件实施合并刷新与在途“待补刷”折叠；搜索框、翻页游标、账号切换与管理端详情抽屉切换全面绑定请求代次，丢弃迟到的过期响应，且修改偏好时按最新 `ETag` 串行提交防止自触发 `412` 版本冲突。
- **流式二进制导出与分路径写超时**：个人数据导出与静态资源直传底层字节流，不在内存中拼接整份临时大字符串，并通过 `http.ResponseController` 将大文件下载写期限（`5m`）与普通 JSON 接口短超时（`15s`）解耦。
